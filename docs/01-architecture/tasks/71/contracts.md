# Issue #71 数据与本地操作契约

> v1 · Accepted · 2026-10-02；数据兼容来自已批准 PRD，内部命令形式已随本次设计获用户批准。
> 无 HTTP API／后台数据库。本契约定义浏览器内协作与存储可观察结果；内部函数名可由 LLD 细化，行为不得静默变更。

## 1. 持久数据与兼容

产品键保持 `page-between-reading-list`，值为 JSON 数组：

```json
[{"title":"长安的荔枝","read":false},{"title":"Dune","read":true}]
```

| 内容 | 类型／约束 | 读写规则 |
|---|---|---|
| 根 | 有序数组 | 顺序是列表顺序；修改书名不得重排 |
| title | string | 保存目标名称 trim；输入长度上限沿用 80 UTF-16 code units；历史字符串不批量 trim／截断 |
| read | boolean | 名称修改严格保留 |
| 其他既有字段 | 未定义历史扩展 | 不为此新增字段；目标浅拷贝更新 title 时保留其他字段，非目标记录原样保留 |
| id／version／draft／filter | 不新增 | 条目关联在当前页面内存；不做持久 schema migration |

加载沿用现有 `loadBooks`：非数组、解析／读取失败返回空内存清单；仅保留 title 为 string 且 read 为 boolean 的有效记录，包含历史长名称与重复名称，不自动写回。后续用户明确写命令仍沿用整个有效内存清单保存的既有行为，不扩展损坏数据恢复承诺。

原型键 `page-between-reading-list-prototype-71` 仅用于演示；首次访问提供三本书，可重置；研发禁止使用原型键、初始示例或故障开关作为产品逻辑。

## 2. 临时状态与目标关联

`currentFilter` 为 `all | read | unread`，启动默认 all，保存改名不改变该值。`editor` 为 null 或 `{book, draft, error}`；draft 是原始输入，error 是条目错误，book 是当前加载周期的目标关联。草稿、错误、焦点、组合输入状态均不写 localStorage。

不得用书名当主键（正在修改且历史可能重复），不得用过滤列表下标作为存储下标。保存前确认目标仍存在；标记替换目标对象时重新绑定 editor；删除其他对象时关联保持目标；目标删除后 editor 置空。

## 3. 修改命令

概念输入：`rename(targetReference, rawTitle)`，由唯一编辑条目的明确保存触发。返回概念结果 `ok` 或 `error(code, message)`；无网络状态码，无幂等令牌。

处理顺序：确认目标存在 → trim 后非空 → 原始输入长度 <= 80 → 与所有其他书籍去重 → 候选快照写入 → 成功提交内存／退出编辑。原始长度按新增 input 的长度口径检查，避免空格或超长粘贴被浏览器静默截断后保存；编辑输入允许呈现完整超限草稿并报错，不设置会吞掉粘贴尾部的 maxlength。内部空格不折叠，不做 Unicode normalization 或新字符规则。

去重键沿用现有 `title.toLocaleLowerCase()`，对新名先 trim；比较对象是整个保存清单而非当前筛选，排除自身。旧条目不自动 trim。保存原名、只去首尾空格、只改变大小写均可，但仍排除与其他对象冲突。旧超长名保持可加载和展示，用户保存编辑时需缩短至上限，不修改历史数据本身。

| 错误码 | 场景 | 文案／状态 |
|---|---|---|
| TARGET_MISSING | 原关联已删除 | 结束失效编辑，告知条目不存在，回到当前筛选 |
| EMPTY_TITLE | trim 为空 | 请填写书名，不能只输入空格。 |
| TITLE_TOO_LONG | 原始输入长度 > 80 | 书名不能超过 80 个长度单位，请缩短后保存。 |
| DUPLICATE_TITLE | 其他条目比较键相同 | 清单中已有同名书籍，请换一个书名。 |
| STORAGE_WRITE_FAILED | 序列化／setItem 抛错 | 未能保存，原书名未改变。请重试或取消。 |

除目标丢失外，任何失败保持保存清单、统计、筛选和原草稿，条目内显示错误、输入标记 aria-invalid 并聚焦。失败返回不报告成功。成功仅改目标 title，保持 read、位置、其他条目，播报 `已将书名保存为《新名》。`，焦点回目标修改按钮。

先构造候选数组，目标用保留其他字段的记录更新；写入成功前不执行 `book.title = ...`、不替换 books、不渲染新保存名。写入失败不尝试清空存储或二次回滚写入。重复原名保存可正常写入再退出；写失败仍保留编辑，重试遵循相同校验。

## 4. 本地保存操作

概念命令 `persist(candidateBooks)`：JSON.stringify + localStorage.setItem 串行同步执行；成功后才能令内存清单等于候选。返回成功或写入失败。持久化改名没有并发队列／异步回调；没有成功前乐观渲染。本地写失败不是“先显示成功再提示刷新”的弱承诺。

编辑草稿不在新增、标记、删除候选中；这些操作只消费保存清单。编辑相关写操作也使用成功后提交原则，以防后续保存把失败修改带入持久结果。该协调不是授权重做产品全局加载错误、恢复或备份功能。

## 5. 交互协调矩阵

| 操作 | 已保存清单 | 编辑草稿 | 筛选／焦点 |
|---|---|---|---|
| 输入 | 不变 | 原始值更新 | 输入保持焦点 |
| 保存有效且写成功 | 只改目标 title | 清除 | 筛选不变；回目标修改按钮 |
| 校验／写失败 | 不变 | 保留，可修正／重试／取消 | 筛选不变；回输入 |
| 取消／Escape（非组合中） | 不变，不写存储 | 清除 | 回原目标修改按钮 |
| 切换筛选（含再次选当前） | 不变 | 清除，无放弃弹窗 | 选择的筛选按钮保持焦点 |
| 编辑另一书 | 不变 | 丢弃旧草稿，预填新目标原名 | 新输入聚焦并选中 |
| 新增失败 | 不变 | 保留 | 新增输入接收错误／焦点 |
| 新增成功 | 按原规则新增 read=false | 清除 | 切回全部；回新增输入 |
| 标记目标／其他书成功 | 仅对应 read 变化 | 不保存；目标仍可见则保留，目标离开筛选则清除 | 重绘后回对应 checkbox；移除则回当前筛选 |
| 标记失败 | 不变；checkbox 恢复保存状态 | 保留 | 可重试，播报失败 |
| 删除目标成功 | 删除目标 | 清除，不复活 | 相邻有效操作或当前筛选 |
| 删除其他书成功 | 只删除其他书 | 保留，不保存 | 相邻操作，避开已移除元素 |
| 删除失败 | 不变 | 保留 | 播报失败，可重试 |
| 刷新／关闭 | 从最后成功保存结果恢复 | 不恢复 | 筛选默认全部 |

## 6. 辅助技术与输入法契约

原生 button、input、form；显示入口「修改书名」且可访问名称包含保存名，输入有显式 label。条目错误 role=alert 并通过 aria-describedby 关联；成功／取消／删除等反馈 role=status，筛选 aria-pressed。

进入编辑聚焦并选中原名；Tab 顺序输入→保存→取消→删除→后续条目。普通 Enter 是明确表单提交；Escape 取消。compositionstart/end 管理组合态；keydown 的 isComposing／组合标志／229 防止候选确认 Enter 被提交；组合态内 Escape 不取消。研发须验证真实中文输入法事件序列及焦点重建，不把工具 fill 中文文本当输入法测试。

## 7. 研发验证入口
