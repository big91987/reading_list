# Issue #97 HLD：页面版本号显示

2026-10-03。目标架构，Runner 自主授权下的可逆设计选择，不表示用户逐项审查批准。上游：[PRD](../../../04-implementation/tasks/97/prd.md)。

## 1. 全景、目标与阶段

```text
Issue 版本声明 → 维护者更新静态页面 → 既有受审查发布流程
                                           ↓
用户打开页面 → 页脚查看版本 → 继续读书清单操作
                                           ↓
                     既有 app.js ↔ 浏览器 localStorage
```

本阶段把需求转换为页面原型、维护责任与兼容契约；研发负责产品实现、LLD、产品回归与发布声明，QA负责独立复核，Owner保留最终合并及高风险发布授权。成功标准为唯一完整的“版本 0.1.0 rc2”可见、不影响书单。非目标沿用 PRD：无自动更新、版本历史、账号、后端或版本编辑入口。

## 2. 驱动因素、上下文与责任

使用者读取版本，维护者声明并随产品变更维护版本，Owner承担产品与发布责任。静态页面为唯一部署单元，沿用当前宿主与访问方式；版本能力没有独立服务、异步任务或外部依赖。

| 能力/事实 | 主责及事实源 | 生命周期/相邻边界 |
|---|---|---|
| 版本识别 | 页面呈现；产品 `app/index.html` 的 `#app-version` 文本 | 维护者声明→交付展示→下一次变更替换；不由书单数据派生 |
| 书单操作与持久化 | 既有 `app/app.js` 与 `page-between-reading-list` | 沿用添加、阅读、筛选、编辑、删除、撤销；不消费版本值 |
| 页面交付与恢复 | 维护者及既有发布流程 | 更新→检查→人工权限边界下发布；出错修复或回退页面，不清除书单 |

来源覆盖及双向核对见 [traceability.md](traceability.md)。版本呈现与既有页面属于同一静态模块，非新增领域服务。

## 3. 逻辑模块与交互

HTML负责静态可访问文本，CSS负责排布，既有JS负责书单；版本无需JS初始化。页脚保留原文，版本另起一行：14px（0.875rem）、1.5行高、字距0.02em、上间隔8px、使用 `--muted` 色。继承现有字体和页脚居中排布，不固定悬浮、不加图标、链接、按钮或 `tabindex`；版本不使用 `aria-live`，不要求悬停，不裁切或省略文本。长清单允许正常滚动到页脚。

页脚在 main 之后的自然文档流，三个筛选、空态、错误提示或刷新均不重建版本。footer以 `max-width:100vw` 限制在实际布局视口内；在320px窗口原生200%形成160 CSS px视口时仍完整呈现版本，不改变既有body/main最小宽度。初次CSS模拟仅是历史证据；当前原生zoom、AX、几何断言及共享门禁状态见 [返工核验](../../../05-validation/tasks/97/design-rework.md)。AX树不代表读屏器语音实测。

## 4. 流程、信息与状态

维护流程：维护者以 Issue 声明为输入→修改产品版本节点→按契约核验唯一完整文本和既有主线→通过既有受审查变更及发布流程交付→检查实际页面；未来替换同一节点并重新核验。首次可用是产品页面交付后可见，不是设计原型已发布。若错误，修复/回退静态声明并复验；与部署内容摘要分开。

调用流程：浏览器加载HTML/CSS→读取版本→继续既有书单JS。版本无请求、重试、持久化、事件或幂等副作用；重复加载得到同一交付文本。书单输入和存储失败沿用现有提示与重试。用户无版本写权限，没有新身份边界、计量或审计事件；变更记录沿用项目审查流程。

版本标识只有交付声明值，没有运行时状态机或独立ID生命周期；书籍数据契约详见 [contracts.md](contracts.md)。

## 5. 部署、安全、故障和质量

| 场景 | 结果/隔离 | 发现及恢复主责 |
|---|---|---|
| JS初始化失败或存储写入失败 | 静态版本仍在HTML；书单错误不隐藏页脚 | 开发/QA故障检查，维护者修复既有异常 |
| HTML/CSS加载失败 | 不能保证页面可用，无新增降级服务 | 维护者按现有交付流程恢复静态文件 |
| 声明陈旧/错误 | 可见标识可能错误，不能代表缓存或部署时间 | 维护者修复文本并对实际交付复验，不要求用户清空存储 |
| 窄屏及放大 | 新文本完整、不遮挡主内容、不新增横向溢出 | 研发复验320px及原生200%，QA复核 |

性能约束：版本0额外请求、0额外存储写，HTML常量开销，无新增容量/SLO承诺。安全约束：不引入凭据、外部脚本、遥测或用户输入注入；版本为审查过的字面文本。可访问性约束：普通可访问文本、无新增焦点、字号14px及色值 `#716b62`，对平坦纸色 `#f4efe6` 计算对比约4.61:1；实际截图仍需人工观察。

## 6. 技术策略、演进与风险

采用既有HTML/CSS能力，不加配置解析、依赖或工具。可信变化仅是维护者将来替换版本文本，窄接缝为单一节点；需要自动发布同步时另立需求。无数据迁移，回退只移除版本节点及样式。研发若变更 `app/`，需本轮实际兼容证据后更新 `deploy/release.json`，不复用旧发布声明，不改工作流/Harness。

非阻断风险：页脚需要滚动才能发现、未来手工声明陈旧。CSS模拟不能替代原生缩放；160 CSS px整页仍保留既有320px最小宽度，不声称修复全部书单布局，版本不得新增溢出。共享工具依赖已解除：用户提供上游修复信息，design复验零写正/负例、原生矩阵和完整verify通过，未降低验收或替换旧门禁。进入development后仍需重新完整复验，再交QA。原型不是线上发布，不承诺缓存立即更新。决策与退出路径见 [architecture-decisions.md](architecture-decisions.md)。
