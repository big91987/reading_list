# Issue #82 HLD：撤销最近一次删除

> v1 修订版 · Accepted · 2026-10-02。用户批准设计、焦点与草稿规则，并授权交接研发；不代表产品已实现或验收。
> 产品语义以 [PRD](../../../04-implementation/tasks/82/prd.md) 为准；设计提案记录在 [台账](architecture-decisions.md)。

## 1. 目标、阶段和驱动因素

目标是减少误删损失，在既有浏览器本地书单中恢复最近成功删除的书名、阅读状态与完整清单序位，且不破坏其他书、筛选和编辑草稿。使用者通过既有新增入口创建持久书籍，新增、改名、标记、删除、撤销负责完整生命周期；Owner 审查阶段成果和草稿 PR，人工决定合并。

全景：已批准需求 → 覆盖与事实调查 → 原型/交互 → 状态与持久化契约 → 浏览器验证 → G2 自查 → 用户批准 → 研发 LLD/计划/实现 → 产品验证/QA。

本阶段回答“失败后哪些数据不能变、用户怎样继续”，不代替研发任务拆解或发布。一个撤销机会是页面内存中的一份被删书快照，不是永久回收站；成功存储是操作生效的边界，不意味着新增后端事务。

驱动因素：单次撤销、不计时、刷新失效；同名冲突拒绝而不覆盖；写入失败必须保持旧清单和机会；320px/1280px 可用；沿用现有 UI、JSON 和编辑规则。非目标：账号、后端、历史栈、多标签协调、倒计时、全站改版。没有新增性能 SLA、容量或云可用性承诺。

## 3. 事实源、状态与一致性（承接已批准规则）

| 信息 | 权威与写入入口 | 派生/生命周期 |
|---|---|---|
| 完整已保存书单、title/read、顺序 | localStorage 的既有 JSON；页面唯一持久化函数接受命令候选 | 成功后内存 books 与持久化相同；UI/统计派生于 books |
| 最近撤销机会 | 页面清单状态；仅成功删除设置/替换 | 成功撤销或刷新变 null；失败和正常其他动作保留 |
| 筛选和编辑草稿/error | 页面交互 | 非持久；保留既有退出规则，撤销不退出编辑 |
| 提示/错误/统计 | 页面交互派生 | 不是数据提交凭证；只有写入返回成功才显示成功 |

状态流：无机会 → 删除写成功 → 有机会；有机会 → 新删除写成功 → 新机会；有机会 → 冲突/写失败 → 原机会；有机会 → 撤销写成功 → 无机会；任意状态 → 刷新 → 无机会。

成功删除先取得已保存对象及完整清单 index，构造不含该书的候选，调用现有 persist，成功后才设置书快照/序位和更新界面。失败不更换旧机会，也不移除编辑条目。删除正在编辑的书只快照已保存版本。

撤销读取当前机会，基于**当前完整清单**按既有 toLocaleLowerCase 规则检查名称；冲突不写入。无冲突在 min(originalIndex, books.length) 插入快照，写入成功才消耗机会。保留现存书对象与相对顺序，避免破坏 editor 对对象的引用。恢复结果不匹配筛选时仍成功，并告知不可见，不切换筛选。不得先改内存再补保存。

单页面同步命令，校验→写入→提交之间没有 await、队列或异步事件。重复撤销在机会已为 null 时无副作用；没有自动重试，使用者修正/解除故障后主动重试。没有服务端事件、计量、身份或审计持久记录；测试日志不进入用户数据。

## 4. 部署、信任、故障与质量

产品仍为 app/index.html、app/app.js、app/styles.css 三份静态资源，运行在用户浏览器。无构建服务、外部请求、数据库或新包。原型用独立键 `page-between-reading-list-prototype-82`，不读取产品键；演示重置和故障工具仅存在于原型。

书名是用户文本，展示使用 textContent，不拼入 HTML。只在已有书对象上保留字段，不新增 ID、schema 版本或持久 undo。localStorage 和内存是页面故障域；刷新会丢失机会但保留最后成功清单，符合 PRD。原来的读取异常处理保持，不将本轮扩展为损坏数据恢复功能。

| 故障/风险 | 用户结果与恢复责任 | 检验方式 |
|---|---|---|
| 删除写入抛错 | B 保留，旧 A 机会保留，原统计/持久化不变；可重试 B 或撤销 A | 真实产品故障注入，见 fault-validation-plan.md |
| 撤销写入抛错 | 未恢复、不消耗机会；恢复按钮仍可用，主动重试 | 同上，解除故障后重试并刷新 |
| 筛选隐藏同名书/大小写冲突 | 拒绝写入，提示先改名，现存书不变 | 原型冲突计划；研发全清单断言 |
| 重绘影响草稿/焦点 | 保留其他 editor 草稿；消失控件有明确焦点去向 | 原型键盘与草稿计划；研发 DOM 值/焦点断言 |
| 多标签独立写同一键 | 不承诺同步或协调 | 已确认非目标，后续需求另行裁决 |
| 页面关闭/刷新 | 撤销机会失效 | 原型 reload；研发真实产品回归 |

质量验收以 PRD AC 为标准：恢复不覆盖、不重复、不改变其他书及统计；320px/1280px 操作可达和无新增横溢出；原生按钮 Enter/Space、可见焦点、role=status/alert；旧 JSON 可读写。每次变更至多 O(n) 的查找/候选数组与一次 JSON 写入，临时快照 O(1) 本书；没有性能实测数字或未批准的最大书量限制。存储配额/浏览器清理不在产品控制内，用失败语义应对。

## 5. 已批准技术与交互方案（A-002）

推荐复用既有 persist 和原生 DOM，在筛选下、清单上增加常驻撤销栏，书名/撤销与普通 operationMessage 分离。清单为空仍显示；不增加关闭入口，不设置 timeout。成功删除焦点移到撤销按钮；成功撤销有其他 editor 时回其输入，否则回恢复条目的修改入口，不可见时回当前筛选。错误留在撤销按钮并通过 alert 通知。详见 [交互规范](../../../04-implementation/tasks/82/design/interaction.md)。

| 方案 | 适配与取舍 | 状态 |
|---|---|---|
| 同页常驻栏＋内存单记录＋既有 persist | 完全承接刷新失效、正常动作保留；改动小，异常可重试 | Accepted |
| 单一临时提示/Toast 复用 operationMessage | 新增/改名反馈会覆盖入口；要额外解决常驻和反馈隔离，退出规则更复杂 | 未选 |
| 持久回收站/历史栈 | 增加数据生命周期和迁移，违反非目标 | 排除，依据已批准 PRD |

主专业视角：状态一致性与恢复（本阶段自查，不启动额外评审模型）。事实：现有 persist 成功后才赋 books，editor 引用书对象，render 重建行。推断：保留候选内现存引用可保持草稿目标；原型证明了重绘后 draft、focus 和继续保存。信心适用于当前单页面同步代码，不推广为多标签/分布式事务。产品故障和兼容的退出标准是全量真实产品 AC 验证，原型证据不替代；不决定范围、QA 结果或合并。

## 6. 演进、兼容、验证与下游责任

无数据迁移。撤销成功写回既有数组，回退 UI 功能时旧版仍可读书单；回退不会还原已经确认删除的书。若未来需要历史/跨刷新/同步，重新确认生命周期和契约，不提前提供 adapter、日志或配置层。当前接缝仅现有 persist、内存记录和独立反馈区域。

原型证明当前交互提案可运行，日志与限制见 [设计验证](../../../05-validation/tasks/82/design-validation.md)。真实产品写入异常方案见 [故障验证计划](../../../05-validation/tasks/82/fault-validation-plan.md)。

故障验证直接以正式注册 check 在 app/ 当前页面执行 storage_write_failure、snapshot_storage/unchanged_storage 和真实 UI 动作，同页关闭故障后重试，再刷新核对。无首页替换、iframe 宿主、实现复制、第二种异常或内部深比较要求；必要内部守卫可独立单元检查，不算用户旅程。该精简方法已按用户审查意见修订，未改变 PRD 承诺。

研发负责：形成 LLD 和实施计划；按 contracts 细化守卫/原子提交/草稿焦点；不移植演示工具；覆盖 14 项 AC，尤其实际写入失败、旧数据、重复点击和 IME/屏幕阅读器证据。QA 根据实际结果判定缺陷返回阶段，不能预设通过。Runner 管理任务分支和草稿 PR，人工决定合并。

G2 自查见设计索引。无改变总体方向的技术未知；真实产品验证是 NEXT STAGE，当前用户已明确批准修订设计并授权交接研发，不再重复审批。
