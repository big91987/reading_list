# Issue #82 数据与操作契约

> v1 修订版 · Accepted · 2026-10-02。用户已批准；产品规则来自批准 PRD，本文件给研发的同步页面契约，不新增网络 API。

## 1. 数据兼容

- 产品键不变：`page-between-reading-list`。值仍为有序 JSON 数组，已知书字段 `title: string`、`read: boolean`。沿用既有 loadBooks 校验、新增 trim/80 长度、改名校验和全清单不区分大小写规则，不新增持久字段或 ID。
- bookSnapshot 是删除时最后保存的书对象浅快照，保留原对象字段；不能从编辑输入框取 title，不重新创建 read=false 的“新书”。现存条目对象仍沿用其引用。
- `undoRecord: null | { book: bookSnapshot, index: nonnegativeInteger }` 仅当前页面内存，index 来自删除前完整清单，非过滤结果。候选插入位置 `min(index, currentBooks.length)`；不得恢复曾删除邻居或早期记录。
- `currentFilter: all | unread | read`、`editor: null | { book, draft, error }` 保持既有内存生命周期，不随 undo 持久化。不增加时间戳、过期时间、历史数组或异步执行记录。

## 2. 命令契约与原子边界

名称描述语义，不强制新增模块/改函数名。操作由当前页面 UI 发起，在同一 JS 同步事件内完成。

| 命令 | 前置/输入 | 成功提交 | 失败/重复 |
|---|---|---|---|
| deleteBook(book) | book 必须仍在完整 books 中；取已保存快照与完整序位 | 删除候选 setItem 返回后提交 books、替换唯一 undo、删除目标 editor（若匹配）、派生统计与渲染；筛选不变 | 缺失目标不写入、不创建机会；写失败保持原 books/editor/undo/统计/存储，反馈失败 |
| undoLatestDelete() | 有机会，按当前完整 books（含隐藏项）校验 title.toLocaleLowerCase() 冲突 | 构造保留现存对象引用的候选，在钳制序位插快照；setItem 返回后提交 books，再置 undo=null，派生 UI 与反馈 | 无机会无副作用；冲突不调用 setItem；写失败不提交候选且保留机会，可重试 |
| persist(candidate) | 候选不提前修改当前 books | JSON 序列化和 localStorage.setItem 成功返回，然后 `books = candidate` | 序列化/写入抛错均返回失败；不能先 mutation/splice 原数组 |
| 既有其他操作 | 沿用已有输入、退出和存储规则 | 只修改原职责状态，不改 undo；新增成功仍切回全部 | 校验/保存失败和编辑取消不得清除 undo |
| reload/open | 按既有 loadBooks 读书单 | undo 初始化 null；筛选和 editor 沿用原初始化行为 | 不扫描存储重建撤销机会 |

消费顺序：校验 → 候选 → 写入 → books 提交 → undo 消耗/替换 → UI。没有 await 或后续补保存。所有失败均不存在“先展示恢复成功再回滚”的中间态。连续用户激活撤销不能重复恢复，成功后入口消失；刷新核对清单及统计无重复。无机会时调用的防守性行为可独立单元检查，不要求调用隐藏 handler 作为真实用户操作。

## 3. 返回结果与可见反馈

| 语义码（仅内部/测试词汇） | 显示 | 数据与焦点 |
|---|---|---|
| DELETE_OK | `已删除《书名》。`，旁有撤销按钮及 `仅可撤销最近一次删除 · 刷新后失效` | 焦点转撤销按钮；清单为空仍可见 |
| DELETE_WRITE_FAILED | `未能删除，请重试。` | 原条目/旧机会不变，焦点留删除按钮 |
| UNDO_OK_VISIBLE | `已恢复《书名》。` | 机会消耗；优先回其他 editor，否则恢复条目的修改入口 |
| UNDO_OK_HIDDEN | `已恢复《书名》。当前筛选下不可见，可切换筛选查看。` | 筛选不变；其他 editor 优先，否则回当前筛选按钮 |
| UNDO_CONFLICT | `无法恢复《书名》：清单中已有同名书籍（可能在其他筛选中）。请先修改现存同名书的书名，再点撤销。` | 不修改任何书，不消耗机会，焦点仍在撤销按钮 |
| UNDO_WRITE_FAILED | `未能保存恢复结果，书籍尚未恢复。撤销机会仍保留，请重试。` | books、统计、机会、存储内容不变，焦点仍在撤销按钮 |
| NO_UNDO / MISSING_BOOK | 不报告删除/恢复成功；不暴露旧机会 | 防守性无副作用；不引入恢复历史功能 |

以上语义码不要求持久化、埋点或外部 API 枚举。错误提示是可访问文本，不以颜色单独传达。书名以 textContent 插入，长文本换行，不用 innerHTML 插值。

## 4. 草稿、视图与焦点不变量

撤销不清 editor、不读取草稿做冲突键、不隐式提交草稿；其他书仍为同一对象，重绘输入应显示 editor.draft 和 error，继续保存/取消有效。新增输入不 reset（除成功新增自身的既有 reset）。删除成功仅退出被删书自己的编辑，失败不退出。过滤或标记隐藏 editor 的既有规则不变。

恢复前当前筛选不变；统计总量和已读数均从完整提交后 books 派生。重建 DOM 后不能把焦点留给已经移除的撤销/删除控件；优先焦点规则见上表。恢复其他 editor 时输入文本保留，输入焦点回编辑框；不承诺重建后保留光标选区/系统输入法候选，研发需验证中文组合门控不回归。

## 5. 测试与兼容出口

原型不是产品契约的实现完成证明。真实产品故障测试直接用注册 check 的 storage_write_failure、snapshot_storage/unchanged_storage、真实 UI 操作与刷新核对。记录书名、统计、错误、撤销入口和存储未变的断言；不要求内部变量深比较、第二种异常或测试宿主。见故障计划。

原序位越界保护在正常单页操作中难以制造：后续成功删除会替换记录，新增只增长长度。本轮原型验证了末尾恢复；必要的 min(index,length) 内部候选边界可独立单元检查，不冒充可达 UI 历史场景，不新增用户验收门槛。产品 AC-10 两条真实旅程仍按 PRD 实测。

旧 JSON 无迁移；以后修改持久格式或加入同步需要另行设计和审批。本轮不测试后端/GPU，也不新增这些能力。
