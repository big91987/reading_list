## 1. 定位、目标与运行责任

输入是 [已批准 PRD](../../../04-implementation/tasks/74/prd.md)、D-001～005 与实际主线产品。输出是同一浏览器书单内的全量派生计数、兼容契约、可运行原型及验证责任。用户确认展示方案后，研发负责 LLD、最小产品变更和正式验证；Owner 审查体验，Runner 负责正式检查和草稿 PR。需求批准不代替设计批准。

```text
用户 → 原有书籍命令 → 本地存储成功 → 当前有效书单 books
                                            ├→ 全量数量 → 三筛选按钮／摘要
                                            └→ 当前筛选 → 可见列表／空态
```

计数是当前有效书单的展示结果，不是另一本账。全部 = 已读 + 未读，不因筛选改变。不新增搜索、账号、服务、API、存储字段、同步任务或迁移。

## 2. 来源与责任域

先按 PRD 全部目标、价值流、对象与质量要求形成 [能力覆盖与追溯](traceability.md)，再映射现有模块。书单管理和阅读状态共用条目生命周期、事实源和失败责任，合并为现有书单责任域；数量与筛选是其只读投影，不是新增领域。

| 模块／责任 | 事实及结果 | 不承担 |
|---|---|---|
| `loadBooks` | 从既有本地键恢复有效集合，损坏或非数组返回空集合 | 数据修复、跨标签协调 |
| 原新增／删除／阅读切换／编辑处理器 + `persist` | 校验、生成候选、保存成功后替换内存书单；失败保持原值 | 乐观计数、独立计数账本 |
| `render` | 从完整 books 派生全部、已读、未读；同步更新摘要与所有计数 | 使用可见列表计数 |
| `getVisibleBooks`、`renderEmptyState` | 按当前分类投影和空态 | 改写书单、改写数量事实 |
| `updateFilterButtons` | 选中态 class、aria-pressed | 存储或维护计数 |

本轮新增内容仅位于现有 HTML 三按钮、渲染计数与必要 CSS，所有现有操作流程保留。数量计算可复用原摘要已读量，总量使用 books.length，未读使用差值；不建立额外全局状态。

## 3. 流程、状态与一致性

首次访问由用户新增书籍建立集合；再次访问由同源 localStorage 载入。首次校验的是加载后的 title/read 有效性，而非假定已有样例书单。新增、修改、标记、删除是持续维护入口；删除退出集合。样例数据只属于原型。

```text
命令 → 既有校验 → 候选集合 → localStorage.setItem
                           ├ 失败：保留 books、按钮数、原书单；提示并允许重试
                           └ 成功：books=candidate → render → 数量与列表同轮更新
筛选 → currentFilter → 选中态 + render；不写存储
刷新 → loadBooks → render；丢弃未保存编辑及原有视图状态
```

同步关键路径，无异步事件、轮询或最终一致窗口。所有成功变更同一次 render 更新三个数字，不要求用户再次点击。书名编辑 render 不改变数量。相同书单重复 render 幂等；现有重复新增校验仍生效；不新增操作幂等键，删除不新增恢复功能。无审计、商业计量或身份控制需求，现有操作提示承担反馈。

## 4. 部署、信任与故障边界

仍为静态 HTML/CSS/JS，运行于单个浏览器页面，同源 localStorage 持久化。Owner 维护静态发布文件，用户维护自己的浏览器书单；无服务器数据库、外部网络调用、新权限或构建依赖。输入书名沿用 textContent 呈现，不引入 HTML 拼接书名。

| 故障 | 行为与恢复责任 |
|---|---|
| 保存不可用／配额等写异常 | persist 返回 false；用户依据原错误提示恢复条件并重试；计数保持原值 |
| JSON 损坏／非数组 | 沿用空集合恢复；显示三个 0，不宣称修复旧数据 |
| 部分条目无效 | 沿用有效性过滤；计数仅针对恢复集合 |
| JS 或静态资源不可用 | 沿用现有应用故障域；计数功能不提供离线备用账本；维护者修复发布 |
| 其他标签页写入 | 无新增 storage-event 同步；当前页沿用现有内存状态，刷新重新加载；非本轮扩展 |

## 5. 质量、验证与技术策略

准确性由不变量和 AC-01～08、10 的正式功能测试验证；原型先验证关键路径。计数额外计算 O(n)、派生空间 O(1)（复用现有已读统计），不再扫描可见集合计数。容量未获用户数字承诺，2468 条只是四位数布局样例，不是性能基准或存储保证。

界面遵循现有视觉和原生按钮语义。AC-09 在 320/430/431/640/641/650/651/1280px 检查 0、样例和四位数：名称数字完整、无新增横向溢出、Tab/Enter/Space 可用。自动可见性与截图检查不等于已测 DOM 几何、真实触摸或读屏；研发承担正式产品检查及人工证据。

| 路线 | 覆盖与代价 | 结论 |
|---|---|---|
| 复用 render，全量派生 | 共享现有成功保存链，数量无独立漂移；不新增模块依赖 | 符合已批准“不增加存储结构”边界，采用此实现方向 |
| 单独维护／持久化计数 | 每个写路径都要协调，失败回滚复杂且出现第二事实源 | 不符合已批准边界，不进入目标架构 |

视觉比较见决策台账：数字直接跟随名称或增加徽标；用户已批准前者及完整设计包。无厂商／库选择、难以逆转的新架构决策，保留一份台账，不另造 ADR 状态库或独立研究报告。证据等级为现有代码事实和浏览器原型，不声称正式产品或后端验证。
