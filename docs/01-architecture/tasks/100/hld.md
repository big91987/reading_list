# Issue #100 HLD：可追溯推荐与本地书籍信息

日期：2026-10-04。设计基线按Runner自主授权形成；非用户逐项审批。业务事实源为[PRD](../../../04-implementation/tasks/100/prd.md)，数据细节为[contracts](contracts.md)。本阶段只交设计和验证原型，未修改app、安装调度或发布。

## 1. 目标、角色与边界

让用户先了解一本书，再主动加入清单；让只有书名的旧书也可补简介，而不把同名作品误当成同一本。官方推荐身份、内容来源与本产品归类分别展示。首批中国作家网文学好书入围书单和福建省图书馆新书推荐，真实两源34条/三非空类型PoC已核对；不宣称全部获奖或最新完整书单。古典文学与仙侠保留筛选入口，暂无内容显示空，不把科幻映射为仙侠。

用户管理本地书单；Owner管理来源、摘要规则、调度、失败报告与限制/异议；官方机构只对其原页负责。无账号、无付费服务、无全网检索、无个人画像和私人数据上传。沿用原origin及存储键。

## 2. 全景与能力—事实—责任

```text
官方公开荐书页 ← 固定白名单HTTPS请求 ← 同机采集进程（Owner）
                                         ↓ 校验/原创短概述/源快照
                                   持久公共目录（唯一写入者）
                                         ↓ 原子替换
浏览器 ← 同origin只读目录路由 ← 既有本机预览服务
  ↓ 用户主动加入/采用/编辑
localStorage私人书单（不进入采集/服务请求）

launchd定时唤起 → due检查/锁 → 采集；停机恢复补检
```

| 能力 / 来源 | 事实与主责 | 边界 / 生命周期 |
|---|---|---|
| 官方接入 R-01、09 | Owner维护来源配置；采集器核验允许域名/推荐语义 | 初次配置、验证、启用、暂停/退出；不接受用户URL |
| 自动更新 R-02、11 | 采集器维护每源最后成功、下一次尝试和报告 | 首次、周期、补检、手动run；私人书单不是输入 |
| 目录及筛选 R-03、04 | 目录为公共事实，浏览器只读缓存 | 来源门类与本产品types分开；失效显示缓存/未知 |
| 加入 R-05 | 浏览器私人条目为用户事实 | 整个书单去重；成功持久化才提示加入 |
| 编辑/补全 R-06、07、08 | 用户确认的元信息快照归书单所有 | 缺失补全、拒绝、多候选、改名待核对；不自动更新 |
| 兼容与恢复 R-10、11 | 浏览器保持旧对象；部署器管理app版本 | 纯加载零写，撤销完整对象，目录故障不影响书单 |

## 3. 逻辑模块与信息所有权

复用静态app，不新增数据库。开发把外部目录加载/校验、书单元信息操作与现有渲染分成可测函数，避免采集逻辑进入app.js。采集脚本负责来源解析和本产品短简介生成、验证及发布；源适配只为两个已核验格式，不设计通用爬虫。摘要采用基于元信息/内容事实的确定性句式，禁止直接截取推荐语；语义不足则排除并报告。维护者审核生成规则/抽样，不逐本手录。私人信息无服务端副本。

目录记录以“规范化题名+作者+出版/版次身份”确定ID；同名不同作者/版次分开。不同源相同身份合并出处，保留逐源简介依据；不以题名跨源强制合并。旧书匹配只按规范化题名生成候选，必须用户选择。旧书没有作者/版次时不推断确定匹配。存储仍数组，对象可选扩展；未知字段保留。

## 4. 部署与运营闭环

运行于既有Owner管理macOS预览宿主。持久根默认`~/.local/share/reading-list-preview`，复用`--root`。新建`recommendations/`保存配置、源快照、目录、状态与报告；不放Runner checkout、不写`releases/`或`current/`。浏览器绝对路径`/__recommendations/catalogue.json`避免index的版本base重写。由产品脚本`scripts/local_deploy.py`服务GET只读特定文件，无目录遍历、无写API、无凭据，仍绑定回环5533。

需要开发新增`scripts/recommendations.py`和受审查的安装器选项。现有预览controller升级需Owner审查后重新安装，因为普通发布不会替换controller；不得改受保护Workflow。`deploy/release.json`数据声明与controller升级审查分别完成，不能以none绕过基础设施变化。只读路由是本产品部署支持，不是共享Harness改动。

| 维护者入口（目标CLI） | 明确结果 |
|---|---|
| `recommendations.py init --root ROOT` | 幂等创建默认配置，首次关闭调度，不清空已有状态 |
| `source list/enable/disable/remove --id ID --root ROOT` | 固定来源ID，修改配置并报告；移除剔除未来公共出处，不删除私人书籍 |
| `validate --root ROOT` | 校验来源配置、内容/权限说明、域名、路径、发布schema；失败不启用 |
| `run --root ROOT` | 无需到期即可采集，锁冲突报告busy；不以开关关闭阻止人工重试 |
| `enable/disable/status --root ROOT` | 默认7天间隔；启用需有效目录和安装能力，关闭保留目录；status含最后成功/错误/下次时间 |
| `tick --root ROOT` | 被调度调用；到期或恢复后执行，未到期/关闭零请求 |
| `install_local_preview.py --recommendations --root ROOT` | 经Owner授权部署更新的controller、worker与launchd；不自动发布app |
| `recommendations.py uninstall --root ROOT` | 关闭并移除本产品采集任务，保留目录/配置/报告；预览服务和私人数据不动 |

调度采用独立标签`com.reading-list.recommendations`、RunAtLoad和1小时StartInterval调用tick；7天是业务due间隔，不是启动间隔。宿主睡眠/关机时不承诺运行；恢复/登录后tick检查due补执行一次，不补跑每个错过的周期。同一轮串行访问，进程锁自动随退出释放，防止手动与周期重叠；下次时间在状态原子保存后可重算，不从launchd进程存在推断成功。正式安装未在设计执行；开发用临时root/受控时钟测试tick，plist结构及参数可自动验证，QA无需等7天。

## 5. 流程、失败与一致性

首次init→validate→run→两源三类型完整目录→Owner审查来源/摘要抽查→安装/启用。以后抓取每源完整候选后构建该源新快照；任一必需条目解析失败/缺简介则该源本轮失败，保留源最后成功，不发布被截断的名单。403/429/robots明确禁止停止该源并报告，robots404不是许可。超时/5xx可重试一次，1秒最小请求间隔，每源50页/2MB单响应/500条/单轮最多5分钟，超限当失败；使用固定HTTPS host和路径前缀，重定向重新校验，私网/非443/任意URL拒绝。

通过全部schema、身份与内容检验的源快照在锁内合并为单文件envelope，用同目录临时文件+fsync+替换发布；公共状态和条目放同一文件，避免状态/目录混版。运行报告另存，崩溃到发布前最后成功仍可用；发布后报告写入失败由下轮恢复状态对账，不能删除成功目录。部分失败显示失败源和各源采集时间，保留旧成功条目并标记缓存；全部失败时不抹去已有条目。首次无有效目录返回503，前端显示失败+重试，与有效空目录区分。来源合法退出可移除出处，无来源的公共记录移除，私人快照不动。

前端fetch只读绝对同源目录，schema支持才替换缓存；缓存用独立键且失败可只保内存。先显示上次成功缓存，再更新，网络/非法目录保持旧缓存；暂无缓存显示加载或失败。手动重试只重读公共目录，不触发采集、不代表采集成功。过期以各源lastSuccess超过7天判定。用户书单模块不依赖目录加载，任一推荐故障可继续添加/编辑/删除。

加入/编辑/采用采用“候选数组→持久化→更新内存”，失败保留原值和草稿。改名保留简介/类型，来源verification置needs_review；查看建议不写。删除缓存完整对象及原索引，一次撤销、刷新失效，恢复失败保留机会。开发保持现有IME、焦点和去重语义。

## 6. 质量与安全验证边界

目录最多1000条/1MB，前端fetch 10秒超时、拒绝不支持版本/过长字段/非法链接，记录安全文本只用textContent。同机HTTP只读与公开来源请求均不得含私人书名、状态、简介；来源链接只HTTPS受控host，rel=noopener noreferrer。研究长简介、封面、网页响应不进入app构建。公开内容未取得概括性许可，原创事实短简介/归属/原页仅是保守使用策略，不是许可认证；Owner可停源处理异议。

320px、原生200%缩放、键盘和真实touch-capable模拟检查新增交互；AX树不是语音测试。本轮原型必须实测成功/重复/存储失败/取消/补全歧义/待核对/撤销/目录状态；生产采集、tick、HTTP路由和发布兼容由development负责测试并交独立QA。具体矩阵见traceability与设计验证。

## 7. 比较、演进与风险

比较：浏览器跨站抓取无法稳定控制/CORS且耦合私人环境；新增在线API服务增加运营/权限，超本期边界；同机离线采集+只读目录复用已存在预览责任，可停止/替换，故采用第三项。代价是新增controller安装支持和Mac登录/开机依赖，需要明确运维而非假装静态文件自动更新。

稳定内核：私人书单快照、确认采用、身份与出处、失败保最后成功。可变接缝：两个源解析器、受控分类映射、摘要句式；来源换页先验证再启用。撤回新app不清理扩展字段，新版无读时迁移；旧app对象扩展保留仍须逐动作验证。源码回滚不恢复用户主动编辑的数据，开发写回滚说明/导出备份，不假设none等级。

非阻断后续事项：上游页面将变、未来新增来源需再次内容/身份核验；正式调度/路由/controller更新未实现，已明确development任务和可执行验证，不作为本设计已完成事实；Owner正式安装与高风险部署仍需人工授权。无阻断目标冲突，无新增财务承诺。
