# Issue #94 PRD：筛选按钮简短悬停提示

日期：2026-10-03。状态：Ready for Architecture（依据 Runner 自主策略完成需求自查，非人工产物审批）。
来源：原始 Issue #94 与本轮用户提供的目标、约束和自主推进授权。决策依据见 [决策记录](requirements-decisions.md)，自查见 [G1](g1-review.md)。

## 1. 背景、目标与成功口径（L0）

读书清单的新用户需要在选择阅读状态前理解每个筛选入口会显示哪些书。当前可通过按钮标签及点击后的列表推断，新增提示让用户在点击前理解含义。问题来自 Issue；没有用户研究或发生频率统计，不宣称量化体验收益。

本轮是现有浏览器产品的一次体验增量：为全部、已读、未读三个入口提供简短中文悬停解释，同时保持已有布局、筛选行为和存储数据。成功口径是三个入口提示语义正确、无需点击即可看到，且回归检查确认既有行为和数据未改变。

非目标：更改筛选顺序或默认值、添加筛选类型、搜索、计数、常驻帮助、引导弹窗、移动端长按交互、数据迁移、账号、后端服务及埋点。

## 2. 用户、运营与责任

直接用户：在浏览器管理个人读书清单的读者，重点是首次使用筛选的新用户。读者通过现有添加入口建立清单、标记阅读状态、使用筛选并关闭页面退出；刷新继续使用既有本地数据。

产品保持本地浏览器自助使用模式。仓库 Owner 负责产品范围、支持反馈和最终合并/发布授权；设计阶段负责提示呈现与原型证据；开发阶段实现并提供功能及回归证据；后续验收责任方按项目流程核验 AC。新增提示不引入运营配置、额外容量或外部付费依赖。

## 3. 产品级业务闭环（L1）

价值流：读者打开既有清单 → 悬停筛选入口并理解显示范围 → 点击所需入口 → 查看对应阅读状态的书 → 按既有方式修改清单或退出。

核心对象是既有书籍、阅读状态和当前筛选范围。书籍由读者通过现有添加入口创建，加入后出现在全部/未读范围；通过已读标记进入已读范围，通过删除入口退出清单。已有 localStorage 清单也可作为首次打开的数据来源，无需新增初始化操作。提示是产品提供的固定解释，不成为可编辑或持久化对象。

业务不变量：全部显示所有书，已读显示已读书，未读显示未读书；悬停不选择范围、不修改书籍、不写入存储；点击继续按现有语义筛选。空清单和筛选无结果不影响入口解释，不替换原有空状态。提示不可用的无悬停环境仍可通过原标签直接筛选，不需要人工恢复步骤。既有存储异常处理保持原状。

## 4. 本轮范围与需求（L2）

所有 R 均为本轮必须交付项；不代表 P0 风险等级。

| ID | 产品结果与规则 | 追溯 |
|---|---|---|
| R-01 | 三个现有入口都有无需点击的简短中文悬停提示；已选中与未选中入口均适用 | 理解筛选范围；US-01；AC-01～03 |
| R-02 | 提示使用下表固定文案，不含动态书籍数或用户数据；离开后不成为常驻内容 | 简短、不干扰阅读；AC-01～03 |
| R-03 | 保持现有入口标签、顺序、正常布局、选中状态和点击行为；不抢占键盘操作，不要求触屏用户先看提示 | 保留现有体验；US-02；AC-04～06 |
| R-04 | 不新增/修改存储格式、键、书籍记录或筛选持久化，不改变已有增删改及刷新行为 | 保留数据；US-02；AC-05、07 |

| 入口 | 提示文案 | 范围语义 |
|---|---|---|
| 全部 | 显示所有书籍 | 不限制阅读状态 |
| 未读 | 只显示未读书籍 | 尚未标记已读 |
| 已读 | 只显示已读书籍 | 已标记为已读 |

提示出现和消失的具体延迟、视觉样式及机制由设计阶段明确，不承诺毫秒级时间；不改变页面常态排布。现有顺序保留为“全部、未读、已读”，Issue 中列举名称不视为重排请求。键盘焦点提示不是本次新增承诺，但原有可聚焦、激活、按钮名称和选中语义须保留。

## 5. User Story

- US-01：作为不了解筛选含义的新读者，我希望悬停每个状态入口时看到简短解释，以便点击前知道显示范围。前置为页面已打开，列表可为空；悬停只展示解释，不执行筛选或变更数据。
- US-02：作为已有清单的读者，我希望提示不影响原有操作，以便继续用鼠标、键盘或触屏筛选，且保留书籍和阅读状态。悬停不可用时直接点击/激活仍有效。

## 6. 可验证验收标准

| ID | 场景、步骤和期望结果 | 验证方法/责任 |
|---|---|---|
| AC-01 | 在支持鼠标悬停的浏览器中分别悬停三个按钮，不点击，按呈现机制等待后分别看到“显示所有书籍”“只显示未读书籍”“只显示已读书籍”；离开后提示按该机制消失，页面没有常驻新增帮助文字 | 设计记录机制和真实悬停观察；开发/验收复核。不能仅用属性存在代替可见性证据 |
| AC-02 | 在混合阅读状态清单下，分别选中三个范围，再悬停每个入口；选中和非选中入口的文案均正确；单纯悬停不改变选中范围或列表 | 真实交互及状态断言；开发/验收 |
| AC-03 | 空清单及已读/未读无匹配结果时，三个提示仍为固定文案，无书名、数量或错误文本；原空状态内容不因悬停变化 | 原型覆盖关键状态，产品交互检查；设计/开发/验收 |
| AC-04 | 对照任务开始的产品基线，常态标签、顺序“全部、未读、已读”、间距、选中样式和正常布局不变；桌面与窄屏无因新增提示导致的排布移动、按钮不可点击或页面新增横向溢出 | 对比截图与实际操作；设计/开发/验收 |
| AC-05 | 准备一已读一未读书，点击全部显示两本，已读仅显示已读书，未读仅显示未读书；选中状态随点击正确变化；悬停不触发点击效果 | 功能自动检查与实际交互；开发/验收 |
| AC-06 | 用键盘 Tab 到达三个按钮并按原有 Enter/Space 激活，仍能筛选且焦点、原按钮名称与选中语义保留；无悬停的触屏操作直接点击即可筛选，不需要额外一次点击以关闭提示 | 键盘与触屏环境交互检查；开发/验收。未测须标明，不以桌面截图替代 |
| AC-07 | 使用含已读/未读及中文书名的既有本地清单，比较悬停、仅筛选和刷新前后的 `page-between-reading-list` 原始存储值，保持一致，无提示相关持久化写入；现有添加、标记已读、改名、删除/撤销主线仍按任务开始的产品行为运行 | 存储比较、写入观察及产品回归；开发/验收 |

本阶段仅完成需求检查，不声称上述产品 AC 已通过。现有核心回归作为后续补充验证，不能代替悬停可见性、键盘、触屏及存储证据。

## 7. 依赖、风险、假设与设计输入

依赖当前产品基线及浏览器悬停能力，不引入网络或外部服务。文案采用可逆默认，依据原筛选语义；用户没有逐字审批。无须等待用户的方向性问题。

非阻断事项：浏览器原生提示可能不能被普通页面截图/DOM检测捕获。设计阶段选择并说明提示机制、支持的实际浏览器环境及可执行验证办法；若使用原生机制，补充真实悬停观察证据并说明自动化局限，不宣称属性测试已证明可见。无悬停环境不承诺提示出现。

设计须交付本次变更的可运行原型、关键状态与证据，以及项目约定的 HLD/契约/评审索引；API、数据契约若无变更须明确记录沿用内容。本需求不预定内部实现。若引入常驻内容、改变点击语义、持久化、扩展到其它入口或新增跨端帮助流程，须回到需求阶段重新评估范围。最终合并和高风险部署仍需人工授权。
