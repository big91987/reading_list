# Issue #71 PRD：修改已有书籍的书名

> 版本：v1，已确认需求基线
> 状态：Ready for Architecture
> 用户已审查 PRD 和 G1 自查，明确批准整份 PRD、接受补充默认行为并要求进入设计；审批原文见决策记录。

## 1. 背景、证据与目标

读书清单用户需要修正已录入的书名，不必删除书籍重新添加。现有替代流程会丢失原条目的阅读状态与位置，增加重复操作。

来源：Issue #71 原始需求；用户对 [D-001～D-003](requirements-decisions.md) 的明确答复；项目现状 `docs/00-global/project.md`；源码 `app/app.js`、`app/index.html`、`app/styles.css`。现有功能包括新增、阅读状态、全部／已读／未读筛选与删除，数据保存在浏览器本地；尚无编辑书名功能。问题频率、实际用户规模和节省时间暂无测量数据，不设虚构增长或性能指标。

**产品目标 G-01：用户能在原条目完成书名修正，保留阅读进度与清单上下文，刷新后仍能看到保存结果。**

成功标准：已读、未读条目均可修改；有效修改在同一浏览器刷新后保留；无效修改及取消不改变已保存书名；现有新增、标记、筛选、统计与删除主线继续成立。以第 7 节 AC 和既有主线回归证据验收。

## 2. 用户、运营模式与责任

- 直接用户：通过桌面或手机浏览器管理个人阅读清单的人，自助添加、修改、标记和删除书籍。
- 产品 Owner：确认需求和设计，判定产品是否符合修正书名的预期，并负责支持与后续范围决策。
- 交付责任：设计阶段交付交互原型、HLD 和数据／API 契约；开发阶段实现并提交真实功能验证证据；Runner 按工作区约定执行最终检查、发布任务分支与草稿 PR，不直接合并。
- 运营边界：沿用无账号、浏览器本地使用方式；首次使用从现有新增书籍入口创建条目。浏览器本地存储是保存结果可持久化的前提。取消编辑退出修改流程，删除条目退出该书的清单生命周期；关闭页面不保存草稿。浏览器清理本地数据不属于产品备份承诺。

## 3. 产品级业务架构与范围

价值流：新增书籍 → 在清单中发现录入错误 → 进入目标条目编辑 → 修改草稿 → 校验 → 明确保存 → 继续阅读管理 → 刷新核验保存结果。

核心能力：书籍管理提供录入、名称修正和删除；阅读管理保留已读状态、统计和筛选；本地保存使成功修改在后续访问中可见。操作由用户发起，产品负责校验与呈现结果。

核心对象：书籍条目具有书名和阅读状态；清单是全部书籍的集合；筛选是当前可见范围；编辑草稿是尚未保存的新书名。草稿不改变书籍身份，不属于已保存清单。

生命周期：书籍由现有新增入口创建并显示，支持变更书名、变更阅读状态和删除；编辑从已保存书名开始，成功保存后退出，失败时保留供修正，取消或离开时丢弃。首次可用核验为新增后能在清单中找到并进入编辑。

本轮 P0：编辑、保存、取消、业务校验、持久化、筛选及删除兼容、桌面／手机可用性、基本键盘和辅助技术可操作性。所有要求构成一条端到端交付切片，不设独立 P1。

非目标：账号、服务端数据库、云端或跨设备同步、标签、评分、书名搜索、批量修改、重命名历史／撤销、草稿跨刷新恢复、多标签页冲突解决、产品视觉改版。未承诺后续迭代日期；只有 Owner 提出新的需求时才重新评估这些边界。

| 编号 | 规则 | 来源与状态 |
|---|---|---|
| BR-01 | 保存前去除新书名首尾空白；结果为空拒绝保存，保留输入及原书名并提示修正。 | D-001 已确认 |
| BR-02 | 不区分大小写，与整个清单中的其他书籍比较是否同名，包含当前筛选隐藏的书；排除目标条目自身。同名拒绝保存，保留草稿。 | D-002 已确认 |
| BR-03 | 保存原名可以正常结束编辑；仅调整大小写可保存为新显示名称，只要不与其他条目同名。 | D-002 已确认 |
| BR-04 | 同时最多一个编辑条目。取消、切换筛选、编辑另一条、刷新或关闭页面均不自动保存草稿；切换编辑时丢弃前一条草稿。 | D-003 已确认 |
| BR-05 | 名称修改不改变阅读状态、原列表位置、书籍数量、已读数量或其他条目；成功后保持当前筛选。 | 原始需求＋整体审查默认 |
| BR-06 | 编辑沿用新增输入的 80 长度限制与长度口径；不静默截断后保存，不增加额外字符限制，不折叠内部空格。既有数据保持可加载，不为此批量改写历史名称。 | 现有输入约束＋整体审查默认 |
| BR-07 | 只有明确保存且持久化成功，才呈现新的已保存名称和成功结果。存储失败保留原已保存名称与编辑草稿，提示失败，可重试或取消。 | 整体审查默认 |
| BR-08 | 删除编辑中的条目不保存草稿，不会在后续保存、刷新或取消时复活。删除其他条目保持既有删除语义，不得保存当前草稿。 | 原始删除兼容要求＋整体审查默认 |
| BR-09 | 既有新增和标记操作不隐式保存书名草稿。正常完成新增后沿用切回全部的现有行为并丢弃编辑草稿；新增校验失败不丢弃草稿。标记操作只影响阅读状态；若条目因标记而离开当前筛选，则丢弃其草稿。 | 整体审查默认 |

## 5. 用户流程与产品级质量要求

正常流程：用户从条目进入编辑 → 原书名预填且输入可操作 → 修改 → 明确保存 → 名称符合规则且保存成功 → 返回该条目的展示状态，看到新名与成功反馈。

异常流程：空名、重名或超长时拒绝保存，说明原因并允许直接修正；不影响原书名、阅读状态或其他条目。持久化失败按 BR-07 处理，不要求用户删除重建。

退出流程：明确取消返回已保存书名；离开编辑按 BR-04 处理，不另设放弃确认弹窗。目标条目被删除后结束其编辑状态。当前筛选仍能正确展示留下的条目与空状态。

| 编号 | 功能／质量需求 | 可观察结果 |
|---|---|---|
| R-01 | 现有书籍条目均有可发现的修改入口，支持原位编辑、明确保存与取消。 | 已读、未读均可完成完整修正流程，不新增重复条目。 |
| R-02 | 对保存请求执行业务校验，错误与该编辑条目关联。 | 用户可理解空名、重名及长度问题并继续修正；无误报自身重复。 |
| R-03 | 成功修改只更新目标名称并持久保存。 | 当前筛选不跳转，阅读状态、顺序和统计不变，刷新后仍是新名。 |
| R-04 | 管理单条草稿及其退出行为，避免隐式保存。 | 任意时刻最多一条编辑中；取消、离开、刷新不写入草稿。 |
| R-05 | 新增编辑功能与原新增、标记、筛选、删除、统计及空状态共同可用。 | 原用户主线无回归；编辑中相关操作也遵守 BR-08、BR-09。 |
| R-06 | 桌面和手机保持既有纸色、暖色强调、字体层次与阅读状态表现。 | 320px 手机及 1280px 桌面视口可完整看到并操作输入、保存、取消、删除和筛选，无新增横向溢出；长名称可读。 |
| R-07 | 编辑流程支持触屏、纯键盘与辅助技术。 | 不依赖悬停发现入口；编辑入口、输入、保存与取消有明确可访问名称和可见焦点；反馈可被辅助技术感知；退出后焦点不落在已移除控件。 |
| R-08 | 本地保存失败时，结果可信且可恢复。 | 不报告成功，不改变原保存值，可修正或重试、取消；不清空现有清单。 |

不引入没有证据的响应时间或容量承诺。显示文本应保持普通书名语义，含符号的名称不能当作可执行内容；具体安全实现交设计。

## 6. User Story

| 编号 | 用户故事及前置条件 | 对应需求与 AC |
|---|---|---|
| US-01 | 作为已录入书籍的用户，我希望直接修正原条目书名，保留阅读进度、位置和当前筛选，刷新后仍可见。前置：清单中存在已读或未读条目。 | R-01、R-03；AC-01、05、06 |
| US-02 | 作为修正书名的用户，我希望无效名称有明确原因并可重试，不覆盖原名或误报自己重名。前置：目标条目进入编辑。 | R-02；AC-02、03、04 |
| US-03 | 作为改变主意的用户，我希望取消或离开时不保存草稿，并能继续管理清单。前置：存在编辑草稿。 | R-04、R-05；AC-07、08、09、10 |
| US-04 | 作为桌面或手机用户，我希望用鼠标、键盘或触屏完成修改，保持熟悉的视觉风格。前置：浏览器打开清单。 | R-06、R-07；AC-11、12 |
| US-05 | 作为遇到本地保存错误的用户，我希望知道失败并能重试，不把未保存书名当作已保存结果。前置：有效修改时本地保存失败。 | R-08；AC-13 |

全部为 P0，均追溯到 G-01 及“发现错误 → 修改 → 校验／退出 → 继续管理／刷新核验”价值流。

| AC | 场景与可观察预期 | 规则／需求 |
|---|---|---|
| AC-01 | 分别对已读、未读条目进入编辑：预填该条目原名；修改为有效新名并保存后显示新名，退出编辑且有成功反馈，不创建新条目。 | BR-05；R-01、03 |
| AC-02 | 将草稿清空或只输入空格并保存：拒绝且说明空名原因，保留编辑；原书名与其他清单状态不变。随后输入有效名可以保存。 | BR-01；R-02 |
| AC-03 | 清单存在 `Dune`，将另一条改成 ` dune ` 并保存：重名拒绝并保留草稿；当 `Dune` 隐藏在另一状态筛选中时结果相同。 | BR-02；R-02 |
| AC-04 | 将 `Dune` 保存为原名、` Dune ` 或 `DUNE`，且无其他冲突条目：允许结束编辑；首尾空白不保留；仅大小写变化可持久保存。长度边界沿用新增：80 的名称可保存，超限不得保存，也不得静默截断后宣称成功。 | BR-03、06；R-02、03 |

| AC-06 | 使用修改前已有的本地清单，修改目标名并成功保存后刷新：新名保留，旧条目的阅读状态、顺序及其他条目仍完整；可继续标记、筛选和删除。刷新是否保留筛选沿用现有行为，不新增筛选持久化。 | BR-05、06；R-03、05 |
| AC-07 | 输入草稿后取消，或刷新／关闭后重新访问：显示最后成功保存的书名，草稿不恢复，不显示修改成功。校验失败后取消也具有相同结果。 | BR-04；R-04 |
| AC-08 | A 条目编辑中，进入 B 条目编辑：A 草稿被丢弃，B 预填自身原名，只出现一个编辑条目。输入草稿后切换筛选：草稿丢弃且筛选正常工作；不出现放弃确认弹窗。 | BR-04；R-04、05 |

| AC-10 | 运行现有新增→标记已读→刷新→状态筛选→删除主线，结果保持一致。编辑时新增失败保留草稿，新增成功正常添加、切回全部并丢弃草稿；标记不保存草稿，目标离开筛选时结束其编辑。 | BR-09；R-05 |
| AC-11 | 在 320px 手机与 1280px 桌面视口分别执行进入、保存、取消、错误修正、筛选和删除；用长名称检查布局，功能均可操作，不依赖悬停且无新增横向溢出，风格与原产品一致。 | R-06、07 |
| AC-12 | 仅用键盘完成进入、输入、保存、取消与错误修正，焦点可见且退出后回到合理的可操作位置；检查可访问名称及状态反馈的辅助技术语义。中文输入组合过程中确认候选词不能误触保存，输入完成后可明确保存完整名称。 | R-07 |
| AC-13 | 在有效修改时模拟本地写入失败：原保存名不变，不出现成功反馈，草稿保留且可取消；恢复写入后重试成功，刷新显示新名。失败不清空其他书籍。 | BR-07；R-08 |

## 8. 依赖、假设与风险

- 依赖与硬约束：沿用现有浏览器本地产品、存储键 `page-between-reading-list` 和已有数据格式；不用后台服务或迁移已有数据来实现本轮修正流程。兼容约束的技术表达由设计给出。
- 已确认规则：D-001～D-003 及原始任务边界，不重复审批。用户整体批准 PRD 并接受补充默认行为；BR-05～BR-09、80 长度沿用、原位编辑、320px／1280px 验收和可访问性要求均已纳入确认基线。
- 保存失败风险：现有本地写入存在失败可能，本轮要求修改路径准确反馈和可重试；不扩展为改造所有旧功能的存储容错项目。
- 本地数据风险：浏览器清理、损坏数据和多标签页竞争仍沿用现有边界，不提供数据恢复或同步。旧名称若存在规则外内容，不因加载或查看而被自动清理；主动改名须通过本轮校验。
- 长名称、手机布局、中文输入与键盘焦点风险由设计原型检查和开发验证覆盖；中文组合输入不能误触保存。
- 无需继续向用户澄清的方向性未知项，需求审批已完成。设计方案仍须在设计阶段另行提交用户审查。
