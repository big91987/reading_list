# 修改书名交互规范

> v1 · Accepted；业务行为以已批准 PRD 为准，布局由本次原型表达。

## 用户操作与关键状态

| 状态 | 视觉与操作 | 焦点／反馈 |
|---|---|---|
| 展示 | 保留已读划线／checkbox；常显「修改书名」「删除」 | 入口可访问名包含书名，不依赖 hover |
| 编辑 | 原书名位置替换成有 label 的输入、长度说明、保存主按钮、取消次按钮；删除仍可见 | 进入聚焦选中原名；最多一条，其他书仍有修改入口 |
| 校验错误 | 输入下方空名／重名／超长提示，不关闭编辑、不裁剪草稿 | aria-invalid、描述关联和 alert；焦点回输入 |
| 保存成功 | 原条目显示新名，阅读状态、列表位置与筛选不变 | 清单下方 status 成功播报；回该书修改按钮 |
| 写入失败 | 原型模拟开关触发；条目提示原名未变、可重试或取消 | 保留草稿；不播报成功；取消仍正常 |
| 取消／离开 | 恢复已保存名；换条／筛选无确认弹窗 | 按契约回入口／筛选／新输入，不隐式保存 |

保持现有纸色、衬线正文、暖红主操作、绿色已读勾与原 panel 层次，不改新增区与页眉。桌面行内保留左 checkbox、中间名称或输入、右侧操作；手机 <=650px 将常显操作放名称下方以保留输入宽度，保存／取消在编辑输入下方，删除另行避免误触。编辑操作最小高度 44px，长名任意换行，网格中间列 minmax(0,1fr)，无悬停才出现的按钮。

提示的「80 个长度单位」对应沿用新增输入的 UTF-16 长度口径，不新增 Unicode 字符计数规范。超限输入完整保留、明确拒绝保存；成功再 trim。完整状态协调矩阵、输入法和焦点细节以 [契约](../../../../01-architecture/tasks/71/contracts.md) 为准，不复制另一份产品规则。

## 原型与产品的区别

原型保留原页面与基础 CSS、实现本次交互，使用独立存储键；演示控制区只服务审查。原型先提供三本书，产品启动方式不变且不自动预置书籍。原型不承诺是可直接合入的产品实现；研发应以已批准原型和契约实现于 app/ 并执行完整验收，不复制验证开关或独立键到产品。

桌面编辑、320px 编辑、错误、失败截图及浏览器动作均在 [验证报告](../../../../05-validation/tasks/71/design-validation.md)。截图检查只能证实截图状态的外观，不能代替输入法、辅助技术或产品功能验收。
