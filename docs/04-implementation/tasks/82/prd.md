# Issue #82 PRD：撤销最近一次删除

> 状态：Ready for Architecture；用户于 2026-10-02 批准整份需求基线及进入设计，包含 BR-09。
> 更新：2026-10-02；原始需求：Issue #82；已确认决策：[需求台账](decision-ledger.md) D-001、D-002。

## 1. 问题、目标与成功标准

读书清单使用者误删书籍后，目前只能重新新增并手动恢复阅读状态。提供无需离开当前页面的最近一次删除撤销，降低误删损失，沿用现有视觉风格。

成功标准：用户能辨认被删除的书、恢复其已保存书名和阅读状态及合理位置；连续删除仅恢复最后一本；冲突和存储失败不损坏现有清单，且能再次尝试。以第 6 节 AC 的真实交互结果衡量，不设未经验证的使用率指标。

## 2. 用户、运营模式与范围

- 使用者：在现有浏览器页面管理自己的清单，通过删除、撤销、改名处理误操作和冲突。
- 项目 Owner：确认需求、审查设计和验收证据，决定草稿产品 PR 是否合并；阶段 Agent 分别负责需求、设计、实现与验证。
- 运营方式：沿用浏览器本地持久化，无账号和后端；用户通过已有新增入口创建书籍，修改名称、标记阅读状态，通过删除退出清单。
- 本轮全部为 P0：最近一次删除提示与撤销、恢复规则、冲突与失败恢复、桌面/窄屏/键盘体验、既有功能回归。
- 非目标：账号、后端、云同步、多标签页冲突协调、复杂历史栈、撤销改名或阅读状态、跨刷新恢复撤销机会、倒计时、全站改版。后续扩展仅在新需求获确认后进入范围。

## 3. 产品级业务闭环

核心对象是已保存书籍、当前清单、当前筛选和一份临时撤销机会。书籍由已有新增流程进入清单；保存成功后可编辑、标记和删除。撤销机会仅由成功删除产生，不是另一份持久化书单。

正常流程：成功删除 → 显示“已删除《书名》”及撤销入口 → 用户撤销 → 保存成功 → 书籍恢复、反馈结果、该机会消耗。恢复后原有编辑、标记和删除仍可使用。

异常流程：同名冲突 → 提示先修改冲突书名 → 用户使用既有编辑功能改名 → 再次撤销。存储失败 → 说明失败、保持操作前清单和撤销机会 → 用户重试。若用户改为成功删除另一条书籍，新的删除替换旧机会；不回退到更早删除。

## 4. 业务规则

| 编号 | 规则 | 依据 |
|---|---|---|
| BR-01 | 仅删除持久化成功后才显示删除成功并产生撤销机会；提示明确书名，清单为空也能找到撤销入口。删除失败不产生新机会，不替换已有机会。 | Issue＋现有保存成功语义 |
| BR-02 | 同时仅一份机会；下一次成功删除替换上一份。成功撤销消耗机会，重复操作不能重复恢复；不提供更早记录。 | Issue＋单次恢复语义 |
| BR-03 | 不设倒计时。新增、改名、阅读状态、筛选、编辑保存/取消及校验失败不静默清除机会；其他操作反馈不遮掉仍可用的撤销入口和所对应书名。刷新或重新打开页面不恢复机会。 | Issue |
| BR-04 | 恢复删除时最后保存的书名及已读状态，不恢复未保存的改名草稿，不改变现存书籍的名称、状态或相对顺序。恢复结果成功持久化后才报告成功。 | Issue＋既有编辑规则 |
| BR-05 | 删除和撤销均保持动作发生时的当前筛选。恢复书不符合当前筛选时仍完成恢复，明确提示当前筛选下不可见，用户自行切换查看。成功新增仍沿用现有切回“全部”的行为，撤销不另行改变筛选。 | Issue＋既有行为 |
| BR-06 | 按整个清单校验同名，包含筛选隐藏的书，沿用现有不区分大小写规则。冲突时拒绝恢复，提示先改名，保留机会；不自动改名、不合并、不覆盖现存书籍。冲突排除后可再次撤销。 | D-002 已确认 |
| BR-07 | 撤销存储失败时，清单、统计和机会保持操作前状态，不报告成功、不复活书籍；提供可理解的失败提示并允许重试。 | Issue 异常要求＋既有保存语义 |
| BR-08 | 撤销不隐式保存或丢弃其他书籍正在编辑的草稿；新增、编辑、标记、筛选原有退出规则保持不变。删除编辑中的书后，仅其已保存版本可撤销恢复。 | 既有能力保留要求 |
| BR-09 | 恢复到删除前在完整清单中的序位；序位超出现有清单长度时放到末尾。序位不按当前筛选计算；其他书籍相对顺序保持不变。 | D-003 用户已明确批准 |

## 5. User Story 与质量要求

| 编号 | User Story／要求 | 追溯 |
|---|---|---|
| US-01 | 作为清单使用者，我希望删除后知道删了哪一本并撤销，恢复原有阅读记录，而不用重新录入。 | BR-01、02、04、09；AC-01、02、03、10 |
| US-02 | 作为继续整理书单的使用者，我希望其他正常操作保留撤销机会，撤销也不改变筛选或损害当前编辑。 | BR-03、05、08；AC-04、05、11 |
| US-03 | 作为遇到冲突或保存失败的使用者，我希望收到原因和下一步提示，修正后仍可恢复，不损坏其他书。 | BR-06、07；AC-06、07、08、09 |
| QR-01 | 沿用现有纸色、暖色强调、字体层次和阅读状态样式；320px 窄屏与 1280px 桌面可读可操作，无新增横向溢出，长书名不遮挡撤销入口。 | Issue；AC-12 |
| QR-02 | 撤销支持触屏和纯键盘；入口有清晰可访问名称、可见焦点，反馈能被辅助技术感知；删除或撤销后焦点落在仍存在且合理的控件，不因列表重绘丢失。具体焦点目标由设计阶段明确。 | Issue；AC-13 |
| QR-03 | 保留现有本地数据兼容性及新增、改名、标记、筛选、统计、空状态和持久化能力；存储失败不能显示假成功。 | Issue；AC-08、09、14 |

## 6. 验收标准

以下均为待执行标准，不是通过声明。开发阶段提供真实交互和失败场景证据；QA 如实核验缺陷及归属，Owner 审查体验及最终验收。设计阶段先用可运行原型覆盖核心交互与状态。

| 编号 | 场景与可观察结果 |
|---|---|
| AC-01 | 分别删除已读、未读书：仅成功删除后显示准确书名和可操作撤销；撤销恢复原书名、状态，数量及已读统计正确；刷新仍保留恢复后的书，但无撤销机会。 |
| AC-02 | 连续成功删除 A、B 后只可撤销 B；撤销后 A 仍不存在，无更早入口；连续激活撤销不会出现重复 B。 |
| AC-03 | 删除唯一一本：空清单状态下仍显示对应书名及撤销；成功恢复后空状态消失。 |
| AC-04 | 删除 A 后分别新增其他书、改名其他书、切换阅读状态/筛选、进入与取消编辑或触发校验失败；均保留 A 的撤销机会，无倒计时清除。刷新后 A 仍被删除且不可撤销。 |
| AC-05 | 在筛选下删除并撤销：保持当前筛选，恢复位置依据完整清单；删除后主动切换到不匹配的筛选再撤销，仍恢复并提示当前不可见，切换到匹配筛选可看到原状态的书。 |
| AC-06 | 删除《活着》后新增同名书，点击撤销：拒绝恢复，提示先改名；新书和其他书保持原状，撤销机会仍在。将新书改名后重试，恢复原《活着》的状态且保留新书。 |
| AC-07 | 删除 A 后将 B 改成 A 的书名，点击撤销：与 AC-06 相同；隐藏在当前筛选之外的同名书及仅大小写不同的书名也必须检出冲突；B 再改名后恢复 A，不撤销 B 的改名。 |
| AC-08 | 已有 A 的撤销机会时，模拟删除 B 的存储失败：B 未被删除，提示失败，仍能撤销 A。成功重试删除 B 后，入口明确更新为 B，A 不再可撤销。 |
| AC-09 | 模拟撤销存储失败：书籍不恢复，统计和现存书不改变，不显示成功，机会保留；解除故障重试只恢复一次，刷新数据一致。 |
| AC-10 | 完整清单 A、B、C，删除 B 后新增 D，撤销得到 A、B、C、D；删除 C 后再删除 A，只撤销 A，得到 A、B；无足够条目承载原序位时追加至末尾，未恢复的条目不复活。 |
| AC-11 | 删除 A 后编辑 B 并输入未保存草稿，再撤销 A：B 的草稿不被保存或丢弃，可继续保存/取消。编辑 A 未保存时删除 A 后撤销，只恢复删除前已保存书名和状态。 |
| AC-12 | 在 320px 窄屏及 1280px 桌面实际操作删除/撤销、空状态、冲突、失败提示和长书名；书名及操作可读可达，无新增横向溢出，视觉延续现有产品。 |
| AC-13 | 仅用键盘完成删除、撤销、切换筛选、冲突书改名并重试；Tab 可到达撤销，Enter/Space 可激活，焦点可见且不落在移除控件；删除、恢复及错误反馈具有可访问文本和状态通知。 |
| AC-14 | 回归新增（含空名/同名校验）、编辑保存/取消、阅读状态、全部/已读/未读筛选、统计、空状态、删除及刷新持久化；旧清单可继续加载，成功新增仍切回全部，撤销不清空或覆盖其他书。 |

### 存储失败的真实验证方式

AC-08、AC-09 必须在真实产品运行时，通过可控故障注入使产品实际使用的本地存储写入抛错，再通过真实删除/撤销入口执行操作；不能仅切换一个错误提示演示状态。分别记录故障注入方式与环境、操作步骤、写入失败被实际触发的证据、失败前后清单与统计、原持久化内容未被覆盖、撤销入口及所对应书名仍保留。解除故障后真实重试，并刷新核对最终持久化结果及没有重复恢复。设计阶段明确可复现方案，开发阶段执行并保存断言/运行日志与结果，QA 据实际证据判断。截图仅补充可见反馈，静态阅读仅作代码检查；未执行、受环境限制或证据不足时标为未验证并说明缺口，不得写成实测通过。

- 开放业务问题：无；本 PRD 整体已获用户批准进入设计。多标签页协调不在本轮范围，不新增同步承诺。
