# Issue #82 交互规范

> v1 · Accepted · 用户已批准焦点和草稿保留规则；原型是批准交互，PRD 是产品规则权威。2026-10-02。

## 布局和视觉

保留“页间”既有米色背景、纸色卡片、衬线标题、赭红强调、列表/筛选/编辑布局。唯一产品 UI 新增项是筛选下、书单上方的常驻撤销栏；桌面书名左、按钮右，窄屏自然换行，按钮最小高度 44px，长书名完整换行，不截断为无法识别的名字。

提示由书名与固定说明组成：`已删除《书名》。` / `仅可撤销最近一次删除 · 刷新后失效` / `撤销删除`。按钮可访问名称包含书名。不放倒计时和关闭按钮；没有普通操作覆盖这块区域的入口。空清单也显示在空态上方。

## 状态和动作

| 状态 | 页面呈现 | 用户动作与下一状态 |
|---|---|---|
| 无机会 | 不显示撤销栏，原有操作照常 | 删除保存成功→有机会 |
| 有机会 | 对应最近成功删除书名＋撤销按钮 | 撤销成功→无机会；新成功删除→替换书名 |
| 冲突 | 原栏仍在，栏内错误提示先修改现存同名书，可能在其他筛选中 | 手动选筛选、既有改名保存后重试，不自动跳筛选或改现存书 |
| 存储失败 | 原栏仍在，栏内说明未恢复、机会保留 | 解除故障重试；不能先显示恢复结果 |
| 恢复成功 | 撤销栏消失；原 operationMessage 显示恢复书名 | 不符合当前筛选时明确说明不可见 |
| 刷新 | 最后已保存清单保留，但无机会 | 新删除重新产生机会 |

删除失败使用普通操作反馈，不动已有撤销栏；其他新增/编辑/标记的反馈沿用原区域，既有机会不会被遮掉。撤销错误保留到下次尝试或新成功删除；改名后不会未经重试宣称已解决。

## 键盘、焦点和草稿

- Tab 顺序沿 DOM：新增→筛选→撤销（存在时）→书籍操作。无正 tabindex、无快捷键劫持。原生按钮 Enter/Space 生效，focus-visible 沿用原样式。
- 删除成功聚焦撤销，使移除条目后焦点不落到 body；删除失败保留当前按钮和编辑态。
- 撤销冲突/存储失败：按钮仍存在，焦点保留；错误 `role=alert`。删除/恢复成功文本 `role=status`/polite，撤销栏与一般反馈分离。
- 撤销成功：优先其他正在编辑书的输入；没有 editor 时恢复书可见→其修改入口；不可见→当前筛选。重绘保留 editor.draft/error，不保存或抛弃草稿。恢复不 reset 新增输入。
- 被删书正在编辑时，只恢复最后保存版本；其他书的草稿可继续保存或取消。筛选、成功新增等退出规则沿用 #71。
- 真实 IME/屏幕阅读器朗读未在原型浏览器工具中实测；不把 fill 当输入法或 DOM 属性当朗读证明，交给研发/人工验收记录。
