## 2. 推荐责任分配及待核验位置

依据 `docs/local-deployment.md`：项目已有Owner管理的macOS本机预览运行模式，回环访问5533，运行目录必须独立于Runner checkout。文档默认持久根为 `~/.local/share/reading-list-preview`；本轮没有访问该目录，也未核实实际安装路径、联网能力或新增采集权限。

推荐复用已有Owner管理的本机宿主承载采集与公共目录，而不是开通付费云服务或让浏览器上传私人书单。这是待授权/可用性核验的执行位置建议，不是已安装的服务或已冻结架构。

| 环节 | 推荐位置与责任 | 必须补齐的证据 / 边界 |
|---|---|---|
| 首次两源采集PoC | Owner管理的现有本机预览宿主，或已存在且无新增费用的联网Runner；Runner/Owner配置可调用入口，design执行本任务脚本与来源核验 | 可执行本任务的入口/工具标识、权限范围和原始请求/响应；只读公开外网、不接触私人浏览器存储，不通过本地browser check绕行外网 |
| 后续默认七天采集 | 推荐同一Owner管理宿主的持久运行区，维护者负责启停/立即执行/报告/恢复；design定义正式运行入口，development实现并验证 | 宿主身份、运行账户、调度权限、持久目录可用性待Owner核实。现有预览launchd服务不等于已有推荐调度；不得自动改已有服务、Workflow或自行安装周期任务 |
| 公共推荐目录分发 | 推荐由上述宿主向现有本机预览提供只读公共目录，Owner维护分发权限，design确定受支持的映射与失败缓存合同 | 具体路径/URL尚未冻结；保持已部署release完整性、发布审查、当前/previous恢复机制，不靠直接修改release或配置绕过治理。预留data目录不能冒充已公开的服务能力 |

## 3. 最小外部补齐请求（D-008）

问题：**请 Runner/Owner 提供哪一种可供本任务实际调用的已授权联网入口？**

- A：现有本机预览宿主的任务执行入口（推荐）。复用现有运行资源；需要Runner/Owner提供注册工具/接口或已配置执行目标，并核实运行账户、公开外网访问及任务权限。
- B：已有无新增费用的联网Runner入口。可先完成来源PoC；还需明确由谁提供长期周期采集与目录分发。
- C：暂时没有可用入口，先由Runner/Owner配置。任务保持阻断，不重复派发无网Session，不削减验收。

请提供入口的工具名/执行目标标识与允许范围；凭据由Owner在运行环境安全配置，不在回复或Git中粘贴密钥。回复“继续”“允许联网”或只有域名/截图并不会创建可执行能力，不能视为依赖闭环。可先提供A/B的实际接口，再由design核验PoC；不要求用户代写采集器或逐本手录。
