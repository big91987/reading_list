# Issue #100 PRD：书籍推荐、类型与简介

日期：2026-10-04。范围：读书清单产品。当前状态：Ready for Architecture（本轮网络恢复、真实两源内容PoC与需求自查后重新判定）；既有目标/AC保留，依据Runner自主策略推进，具体方案未获用户逐项审查批准。不沿用旧放行作为本轮证据。

## 1. 背景、来源与现状

用户要求：“自动从网上一些权威网站上找……官方的推荐……各种各类的”；书籍增加类型，例如“古典、仙侠”；推荐书和已有书需要简介，便于判断是否阅读。用户未指定网站、更新频率或分类体系。

当前 `app/index.html`、`app/app.js`、`app/styles.css` 是静态浏览器书单，已支持添加、改名、阅读状态、状态筛选、删除与撤销。有效旧记录至少含书名和阅读状态；存储键为 `page-between-reading-list`，没有账号或服务端书籍目录。当前条目没有类型或简介。事实以本轮代码为准，项目文档中旧任务发布状态不代替代码证据。

用户目前需自行找书，并只能凭书名判断。没有频率、活跃人数或效果统计，不编造推荐转化率。代码事实及来源依据见 [research.md](research.md)，选择依据见 [requirements-decisions.md](requirements-decisions.md)。

## 2. 目标、成功标准与非目标

- G-01：用户能查看跨类型、来源可追溯的官方推荐及简短简介，并选择加入自己的书单。
- G-02：新书与已有书均能具有类型和简介；历史书单可安全补全，无法确定的内容明确缺失。
- G-03：推荐自动更新形成持续可用闭环；外部来源失效不破坏已有推荐或私人书单。
- G-04：保留现有读书清单操作、数据和本机发布治理。

首版成功：真实采集至少两个独立官方机构/组织网站，形成至少三个非空类型的推荐目录；每条可加入的推荐含书名、类型、非空简介、可核对的推荐出处；新书加入、旧书补全、失败恢复与回归全部具有证据。不承诺穷尽所有类型或为任意书名自动找到内容。

非目标：个人兴趣画像、算法个性化、聊天式荐书、购买/下载正文、书评社区、账户和云同步、付费数据服务、任意网址抓取、全网搜索引擎、版权内容全文镜像。不上线新增付费基础设施，不修改 Owner 工作流或共享 Harness。

## 3. 用户、运营与责任

- 书单使用者：查看推荐、按类型浏览、了解简介、加入书单、补充或修改自己的书籍信息；沿用当前浏览器本地使用方式。
- 仓库 Owner / 产品维护者：维护公开来源清单与采集运行入口，启停自动更新，查看失败报告、调整来源及处理异常；支持入口为现有 Issue。无人值守更新可关闭、手动恢复，关闭不清空已发布目录。
- 官方来源机构：提供公开推荐名单和可核对资料；不是本产品的运营者，不承诺其页面稳定或授权本产品任何未明确许可的使用。
- Owner 承担产品运营、内容来源与发布风险。用户可移除个人条目；清理浏览器数据的既有退出行为保留。停用推荐或来源不撤回已加入的个人书籍。

首次可用路径：维护者按受支持的配置/命令入口选定来源 → 运行自动采集并审查来源和异常报告 → 验证并提供首份有效目录 → 用户无需填写来源或联网密钥即可浏览 → 维护者启用可逆的周期更新。不是要求维护者逐本录入；只有预置演示数据不算首版完成。启停、立即执行、查看结果、失败重试与卸载/退出必须有正式运行说明，不允许依赖数据库直改。

## 4. 业务架构与价值流

能力：官方来源接入与更新、推荐目录及类型浏览、书籍信息查看、加入书单、旧书补全与手动维护、更新状态与失败恢复。

对象及生命周期：

| 对象 | 来源与首次可用 | 变更与退出 | 不变量 |
|---|---|---|---|
| 可信来源 | 维护者经受支持入口配置；核对所属机构、具体推荐页、可访问性与使用边界 | 修改、暂时停用、重试、移除；记录原因 | 不把商业热榜或搜索摘要标成官方推荐 |
| 推荐目录/条目 | 自动从启用来源提取，内容完整且出处有效后进入目录 | 周期更新、去重、来源撤回或解析失败；保留最后成功版本 | 每项推荐身份与简介来源可追溯，不含执行性外部内容 |
| 书籍类型 | 首版受控类型集合，来自来源信息或明确标注的本产品分类 | 用户修改自己的类型；维护者调整映射 | 不冒充官方分类；分类不能改变阅读状态 |
| 私人书单条目 | 既有记录、手动添加或用户主动加入推荐 | 编辑信息、阅读、删除、撤销 | 不因采集/浏览/补全建议而自动加入、删除、改序或改变阅读状态 |
| 补全建议 | 已有书名与目录候选匹配，展示候选身份和出处 | 用户采用、拒绝、手动填写；改名后重新核对 | 不凭同名静默确定身份，不覆盖用户已写信息 |

主价值流：自动更新目录 → 用户按类型查看书名、简介与来源 → 主动加入未读书单 → 查看与维护书籍信息 → 阅读、筛选和删除/撤销。旧书流：保留旧记录 → 查找目录中的补全候选 → 用户确认候选并选择采用缺失信息，或手动填写 → 保存后刷新仍可查看。

异常流：来源不可达/页面变更 → 本来源不发布无效更新并报告 → 其他来源继续，保留本来源最后成功内容并标明旧数据；全体失败亦不清空缓存。没有缓存则展示空状态及重试说明，不显示伪造推荐。内容候选不明确则由用户选择；存储失败保留草稿与原数据，提示重试，不假成功。

## 6. User Story 与异常结果

- US-01：作为书单使用者，打开推荐后按类型查看简介与出处，判断是否值得读；无匹配时看到明确空状态，不能把加载失败误认为没有书。
- US-02：作为已选择一本推荐的用户，主动加入书单并保留其简介，随后能按原有流程阅读；重复加入不改变已有条目，写入失败可以重试。
- US-03：作为已有书单用户，查看或编辑新旧书类型和简介后保存，刷新仍保留；取消不保存，失败保留原值和草稿，删除可撤销完整条目。
- US-04：作为只有旧书名的用户，查看补全建议及身份信息，确认后采用缺失信息；同名歧义不静默补全，无候选可自己填写，拒绝建议不产生写入。
- US-05：作为维护者，配置、核验来源并运行自动更新，按周期持续提供目录；来源失败能定位并重试，正常来源不被连带清空，停用与恢复不会破坏私人书单。

## 8. 外部依赖、风险、假设与设计输入
