# Issue #76 PRD：书籍清单页视觉与交互改版

> 版本：v1，已确认需求基线
> 状态：Ready for Architecture
> 日期：2026-10-02
> 已确认方向：A「现代编辑式书房」。用户在整体审查请求后回复「进入设计阶段吧」，批准本需求基线并授权交接；批准原文及范围见 D-002。

## 1. 背景、问题与证据

用户希望浏览和管理书籍时获得更有质感、更有反馈的体验，要求明显重做视觉布局与交互，先讨论方向、再审查原型。

当前改造对象是 `app/index.html` 的“页间 · 读书清单”完整单页，包含页头、新增区、阅读统计、全部／未读／已读筛选、书籍条目、空状态和页脚；没有单本书详情页。`app/styles.css` 当前使用纸色背景、衬线排版、纵向面板和列表行，只有少量颜色过渡。`app/app.js` 已具备新增、修改书名、阅读状态切换、筛选、统计、删除和本地保存能力。本轮证据来自源码阅读，尚未运行本轮原型或产品浏览器验证。

需求来源：Issue #76 原始需求；用户对 [D-001](requirements-decisions.md) 回复「A」；[项目现状](../../../00-global/project.md)；当前源码；[Issue #71 已批准 PRD](../71/prd.md) 与 [需求决策](../71/requirements-decisions.md)。#71 中未实现编辑的历史描述不代表当前代码，当前已有编辑能力。#71 的视觉延续约束由本轮明确的改版要求替代，其他业务规则复用。

问题频率、用户规模和量化满意度暂无测量，不虚构增长或提效指标。

## 2. 产品目标与成功标准

**产品判断：在保留个人本地阅读清单管理能力和数据的前提下，用现代编辑式书房的视觉层次和自然反馈，让用户更清楚地浏览书籍、理解状态并完成管理。**

| 目标 | 用户结果 | 成功标准 |
|---|---|---|
| G-01 | 浏览体验有明显的新布局和层次 | 原型对比当前页，能识别新的页面区域组织、卡片表达和排版层级；用户批准整体视觉，不能仅凭色彩变化判定完成。 |
| G-02 | 管理动作准确、数据不退化 | 新增、重命名、状态切换、筛选、统计、删除及刷新持久化回归成立；旧数据可直接使用，失败不假报成功。 |
| G-03 | 动效帮助理解变化而不拖慢管理 | 可体验并验证选定动效、连续操作、减少动态效果、键盘及触屏场景，操作不等待动画结束。 |
| G-04 | 两端呈现和交付可审查 | 桌面／手机原型经用户确认；实现后提供真实浏览器结果、截图、动效过程证据及草稿 PR，由 Runner 发布。 |

## 3. 用户、运营模式与责任

- 直接用户：在桌面或手机浏览器自助维护个人阅读清单的人；首次通过页面新增入口创建书籍，后续浏览、修改、标记、筛选或删除。
- 产品 Owner／本次用户：批准需求基线、交互原型与设计，判断视觉是否符合预期，承担产品范围、支持与风险决策。
- 设计责任：在已选方向内交付可直接查看和体验的原型、关键状态、动效说明、HLD、契约、追溯和评审记录；不再次要求选择同一视觉方向。
- 开发责任：对照批准原型与契约实施，验证功能、兼容数据、响应式和动效，提供真实证据；偏差需记录并由用户确认。
- Runner：执行最终检查、发布任务分支和草稿 PR；不直接合并。

运营保持无账号、无后端的浏览器本地模式。存储可写是保存成功的前提；同一浏览器同一来源刷新后可读取成功保存的数据，不承诺跨设备或更换来源后的数据同步。取消／离开编辑退出草稿流程，删除退出该书的生命周期；清理浏览器本地数据不属于本轮备份承诺。支持通过 Owner 反馈问题，无新增运营控制台、商业计费或容量管理能力。

## 4. 产品级业务架构

**价值流：**打开清单读取已有记录 → 浏览书籍与阅读概览 → 新增一本未读书 → 筛选并找到目标 → 修正书名／切换阅读状态 → 查看反馈和统计 → 删除不再保留的书 → 刷新确认保存结果。

| 能力 | 用户结果与责任 | 边界 |
|---|---|---|
| 浏览与发现 | 产品呈现可读书名、阅读状态、统计和当前筛选；用户定位目标 | 不增加检索、排序或推荐服务 |
| 书籍管理 | 用户新增、就地重命名、删除；产品校验并反馈结果 | 不增加作者、真实封面、评分或批量操作 |
| 阅读管理 | 用户双向切换已读／未读；产品更新筛选结果和统计 | 不增加阅读进度百分比或笔记 |
| 本地保存 | 产品仅在成功写入后呈现已保存结果，后续访问复用记录 | 无账号、云同步或数据库迁移 |
| 体验反馈 | 产品统一正常、空、错误和操作反馈；动效辅助理解变化 | 不以动画改变业务结果，不为动画延迟可用 |

核心对象：书籍（书名、已读状态）、清单（已保存书籍及顺序）、筛选（当前可见范围）、编辑草稿（未保存的新书名）。视觉卡片是书籍的呈现，不新增真实元数据。

首次可用：用户经现有新增入口输入有效书名，成功后能在全部清单找到未读条目，统计增加，刷新仍存在；已有书籍由当前本地保存记录读取。变更入口是条目编辑和状态切换，退出入口是删除。草稿从原书名开始，经保存结束或经取消／离开丢弃。

关键异常：无效书名不提交；写入失败维持最后成功保存的数据，提示修正或重试；筛选无结果显示对应空状态；动画中途被新操作打断时按实际最新结果呈现。存储读取异常沿用当前容错边界，不承诺修复损坏记录；打开页面不得为了视觉初始化覆盖或清空原始保存内容。

## 5. 当前范围与非目标

本轮全部必需需求为 P0，交付上述端到端闭环；不额外划分未承诺的 P1 功能。

**范围：**整页视觉布局、书籍卡片、排版、配色、层次、桌面与手机呈现、动效与反馈体系；保留现有全部管理能力、数据规则及辅助操作路径；可体验设计原型与真实浏览器验证。

**非目标：**新增单本书详情页、账号、云同步、后端、导入导出、真实封面抓取或上传、作者／标签／评分、搜索、排序、拖拽管理、批量操作、主题切换、删除撤销、编辑历史、草稿跨刷新恢复、多标签页冲突解决，以及无关应用或 Harness 工具改造。装饰性书籍图形可以由设计提出，但不要求用户补录信息，也不暗示已有真实封面。

上述后置能力只有 Owner 提出新需求时重新评估，不承诺后续日期。现有遗留页面使用规则在本轮回归范围内，不将 #71 的历史人工验收缺口当作已经完成的证据。

## 6. 业务规则与不变量

| 编号 | 规则 | 来源 |
|---|---|---|
| BR-01 | 保持当前存储键、数据格式和已有记录可用；不要求用户重录。首次加载不批量改写书名、阅读状态或顺序。 | 原始需求、当前代码 |

| BR-04 | 同时最多一个编辑条目，就地预填并显式保存／取消；取消、切换筛选、编辑另一条、刷新／关闭页面不自动保存草稿。 | #71 已确认规则 |
| BR-05 | 修改成功仅改变书名，不改变已读状态、位置、总数、已读数或其他条目，保留当前筛选。 | #71 已确认规则 |
| BR-06 | 新增成功追加未读书籍并切回全部；状态切换保留当前筛选，条目不匹配时退出可见列表；删除仅移除目标，统计按全部已保存清单计算。 | 当前代码 |
| BR-07 | 只有持久化成功才显示操作成功和最终数据；失败保留最后保存结果，可重试。重命名失败保留草稿和编辑入口；失败删除不移除，失败状态切换恢复原状态，失败新增不丢失输入。 | 当前代码、#71 已确认规则 |
| BR-08 | 编辑期间删除目标不保存草稿、不复活条目；状态切换不隐式保存书名，条目仍可见时保留编辑，退出当前筛选时退出编辑。 | #71 规则、当前代码 |
| BR-09 | 动画只表达状态；快速筛选、多次状态切换、连续新增／删除或编辑时，不重复提交、不展示过时结果、不改变其他书；操作可在动画结束前完成。 | 原始需求，本轮验收具体化 |
| BR-10 | 阅读状态、成功和失败不只靠颜色或运动区分；触屏不依赖 hover，键盘路径与可见焦点保留，条目退出后焦点有合理落点。 | 能力不退化、#71 可访问性基线 |

## 10. 依赖、风险、假设与设计输入

- 依赖：当前产品与 #71 已批准业务规则；Owner 的需求／设计评审；Runner 提供真实浏览器验证通道、证据查看方式和最终发布。使用 Owner 配置的原生浏览器工具，不以 shell 沙箱无法启动浏览器为理由要求用户代提供截图。
- 数据风险：视觉卡片不得依赖旧记录不存在的字段；存储来源不变，新 UI 不清空已有数据。当前损坏数据恢复、备份及多标签页一致性不在承诺内。
- 动效风险：整列表重绘可能引起反复入场、焦点丢失或快速操作错位；设计应确定条目变化与动效中断的产品行为，开发以真实场景验证，不在需求阶段指定动画库或实现算法。
- 可用性风险：卡片留白、窄屏长书名、隐藏操作会影响管理效率；用 AC-02、12、13 检查。偏好减少动态效果时仍要能理解结果。
- 当前基线是纯本地清单，暂无真实异步加载需求；是否存在必要等待交设计说明，不人为新增网络依赖或假等待。
- 验证视口、100 本夹具与可访问性具体化已随本 PRD 整体批准；100 本仍仅为测试夹具，不是容量上限或帧率承诺。
- 不存在待选择的方向问题，需求基线已获用户批准。精确色值、布局、动画时长／缓动、候选取舍及预览方式交设计，在可体验原型中审查。
