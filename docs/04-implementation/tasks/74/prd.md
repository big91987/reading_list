# Issue #74：筛选按钮显示书籍数量

状态：Ready for Architecture · 用户已批准需求基线并授权进入设计 · 更新：2026-10-02

## 1. 背景与证据

读书清单用户希望不必逐个切换筛选，就能知道完整书单的总量及阅读进度。原始来源：[Issue #74](https://github.com/big91987/reading_list/issues/74)及本轮用户提供的完整需求；问题频率与使用人数没有量化证据。

当前工作区 `app/index.html` 提供“全部 / 未读 / 已读”三个筛选按钮，按钮没有数量；`app/app.js` 已提供全清单总量与已读量摘要、添加、删除、阅读状态切换及书名编辑。数据保存在浏览器本地，用户当前可通过顶部摘要获知部分进度。

基线采用 Runner 准备的当前主线实际代码：工作区 HEAD 与本地 `origin/main` 均为 `bff9bb10eafb548783c8cb7b8adb0cfb9b6f0a8c`（Implement reading-list Issue #71 (#73)），三个产品文件没有差异。此核对为本地引用证据，未联网更新远端引用。当前代码没有搜索入口或检索逻辑，已包含书名编辑；[项目现状](../../../00-global/project.md)与[Issue #71 历史任务索引](../71/README.md)中的“尚未合并”属于历史记录，不用于否定实际代码基线，也不重新审批其产品决定。

用户已明确确认（D-004）：本次不新增搜索，以当前主线实际已有功能为基线，只增加三个筛选按钮的全量书单计数。用户已审查并批准完整 PRD，明确保持现有按钮顺序和原功能，授权通过注册工具进入设计（D-005）；不重复审批同一需求。

## 2. 产品目标与成功标准

- G-01：打开书单即可从三个筛选按钮同时获知总量、已读量和未读量，无需先切换筛选。
- G-02：成功添加、删除或改变阅读状态后，三个数量立即反映完整书单；正常保存后刷新，数量与恢复的书单一致。
- G-03：桌面及手机上的筛选仍可用，保留既有本地数据、操作流程和视觉风格。

成功标准为本文件 AC-01～AC-10 可观察地成立。不增加访问量、响应毫秒数或采用率等无依据指标。

非目标：新增搜索、阅读进度百分比/统计图、独立统计页、账号与后端、云同步、跨标签页实时同步、新存储结构或迁移、重排筛选按钮、改写既有书籍校验规则。不新增搜索及仅增加全量计数的边界已经用户确认，不再重复询问。

## 3. 用户、运营模式与责任

直接用户通过现有浏览器页面管理自己的本地书单，无需申请账号；首次使用可从空书单开始，通过新增书籍进入使用流程。用户维护书名与阅读状态、删除不再保留的条目，并决定是否保留本地数据；关闭页面不会删除已保存书单。

项目 Owner 负责产品范围、需求/设计确认和最终验收，维护者负责现有静态应用及问题修复。仍使用浏览器本地存储；本轮不新增运营服务、预算承诺、服务容量或数据托管责任。浏览器清理本地数据后按空书单展示，不承诺数据恢复。

## 4. 产品级业务架构与核心对象

价值流：打开页面 → 恢复本地书单或获得空书单 → 查看三个全量数量 → 按阅读状态筛选 → 管理条目 → 成功保存后查看更新数量 → 刷新再次核对。

| 对象/能力 | 来源、责任与生命周期 | 不变量/业务结果 |
|---|---|---|
| 书籍条目 | 用户通过现有新增入口创建，初始未读；可修改书名、切换已读状态或删除；已保存条目从现有本地书单恢复 | 修改书名不改变数量；删除条目退出统计范围 |
| 完整本地书单 | 当前页面成功恢复和成功保存的条目集合 | 作为所有按钮的唯一统计口径，不按当前可见条目计数 |
| 阅读数量 | 根据完整书单及现有阅读状态派生 | 全部 = 已读 + 未读；三个数均为非负整数；空集合均为 0 |
| 当前筛选视图 | 用户通过现有按钮选择 | 只改变可见条目和选中状态，不改变统计口径或书籍数据 |

异常闭环：新增校验失败或保存失败时保持原书单与原数量，沿用当前错误提示及重试路径；切换状态或删除保存失败同样不提前改变数量。非法/损坏本地数据沿用当前恢复行为，仅统计应用成功加载的有效条目，不新增修复或恢复功能。

## 5. 范围与业务规则

本次为现有读书清单的增量功能，所有需求均为 P0；没有新增平台能力或独立服务。

| ID | 需求/规则 | 目标与流程 |
|---|---|---|
| R-01 | 三个筛选按钮持续显示各自名称和精确数量，例如“全部 3”“未读 2”“已读 1”；沿用现有按钮顺序 | G-01，查看进度 |
| R-02 | 统计完整有效书单；切换筛选不会改变数量；统计逻辑不依赖可见条目 | G-01，查看与筛选 |
| R-03 | 成功新增后总量及未读量各加一；成功删除后总量及对应分类量各减一 | G-02，维护书单 |
| R-04 | 成功从未读切为已读时已读加一、未读减一，反向相反，总量不变；书名编辑数量不变 | G-02，维护条目 |
| R-05 | 无需刷新、重新点击按钮或等待轮询才能看到成功操作后的数量；重新加载时与实际恢复的书单一致 | G-02，保存与恢复 |
| R-06 | 空书单三个按钮均显示 0；分类为空时仍可选择该按钮，保留既有分类空态 | G-01/G-03，空态 |
| R-07 | 保留当前筛选、选中状态、键盘操作、书籍顺序、顶部摘要、新增成功返回全部及编辑流程；沿用现有视觉风格，名称与数量可同时辨认 | G-03，完整使用流程 |
| R-08 | 保留原本地存储键及数据格式，不新增后端或计数存储；保存失败/校验失败不把未生效操作计入数量 | G-02/G-03，异常与恢复 |

整数显示不用“99+”等近似值。徽标、间距等表现细节由设计阶段确定，须满足名称、数量、选中态及可访问性可辨识；不预定内部实现。

## 7. Acceptance Criteria

统一样例：有效书单包含 A（已读）、B/C（未读），初始数量为全部 3、已读 1、未读 2。验收责任：研发提供功能测试与实际浏览器证据；设计提供桌面/手机可运行原型及关键状态证据；Owner 审查体验及最终结果。需求阶段不声称已执行产品测试。

| ID | 场景与预期结果 | 验证方式/追溯 |
|---|---|---|
| AC-01 | 初次打开样例书单时，三个按钮同时显示正确名称和数量，全部选中；顶部摘要仍为共 3 本、已读 1 本 | 浏览器断言与截图；R-01、07 |
| AC-02 | 依次选择已读、未读、全部，列表分别为 A、B/C、A/B/C；三个数量始终为 3/1/2，选中态与原按钮语义正确 | 功能回归；R-02、07 |
| AC-03 | 从样例新增 D 后为 4/1/3；删除已读 A 后为 3/0/3；再删除未读 B 后为 2/0/2。各步骤保存成功即可见更新 | 浏览器动作及断言；R-03、05 |
| AC-04 | 从样例将 B 标记已读后为 3/2/1，再标记未读恢复 3/1/2；在分类视图操作时即使条目离开视图，三个数仍立即正确 | 两个方向及分类视图断言；R-02、04、05 |
| AC-05 | 成功新增/删除/状态变更后分别刷新，三个数量与刷新恢复的有效条目及阅读状态一致 | 持久化回归；R-05、08 |
| AC-06 | 空书单三个数均为 0；仅未读时已读为 0，仅已读时未读为 0；零数量分类仍可点击并展示现有空态，三个数不变 | 空态浏览器检查；R-06 |
| AC-07 | 提交空书名/重复书名或模拟新增、删除、阅读状态保存失败时，书单和三个数保持原值并展示现有失败反馈；恢复存储后重试成功只计一次 | 错误注入功能验证；R-08 |
| AC-08 | 样例中保存有效新书名、取消编辑、提交无效编辑分别验证：书单数量始终不变；原编辑规则、顺序、筛选、焦点流程不因新增数量被改变 | Issue #71 相关回归；R-04、07 |
| AC-09 | 设计选定并记录的桌面与手机视口下（至少覆盖现有 430px 及 640px 响应式断点两侧），三个名称及精确数量不被遮挡/截断、无新增页面横向溢出；0、样例及至少四位数计数可辨认；鼠标、触摸、Tab/Enter/Space 可操作筛选，焦点可见，辅助技术能识别筛选名称、数量和选中状态 | 可运行原型与产品浏览器证据；可访问性检查应注明自动/人工覆盖边界；R-01、07 |
| AC-10 | 既有本地书单无需迁移即可加载并正确计数；损坏 JSON 或无效条目按既有加载行为处理，按钮显示应用实际恢复集合的数量；保存数据仍沿用原键及格式，无额外计数结构或后端依赖 | 加载样例、存储对比和代码检查；R-08 |

搜索验收边界：已确认不新增搜索，实际基线没有搜索功能，不设置本轮搜索验收项，也不虚构搜索回归证据。三个数量始终以完整书单为准。
