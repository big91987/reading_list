# Issue #82 真实产品存储失败验证计划

> NEXT STAGE · 2026-10-02 修订。仅承接 PRD AC-08/09 及既有重试/刷新要求，不增加验收门槛。真实产品尚未实现，本计划尚未在 app/ 执行。

## 正式工具与入口

使用注册 `check`，产品根为 `app`，计划为同目录 [product-storage-failure-plan.json](product-storage-failure-plan.json)。从工具的隔离空书单开始，通过真实新增、标记、删除和撤销 UI 建立与操作测试数据。不复制产品实现、不临时替换首页、不使用 iframe 宿主，也不向产品加入故障开关。

- `storage_write_failure(enabled: true)`：使当前页面实际 localStorage.setItem 抛 QuotaExceededError；不修改已有存储内容。
- `snapshot_storage` → 真实删除/撤销 → `unchanged_storage`：核对失败前后持久化未改变。
- `storage_write_failure(enabled: false)`：在**同一页面**解除故障，再由真实 UI 重试。不能先刷新解除故障，因为刷新会按产品规则丢失机会。
- 重试成功后 `reload`，通过书名、统计、阅读状态筛选与撤销入口缺失核对结果和无重复恢复。

以上能力来自正式注册工具。用户告知源仓 PR #39 / 测试仓 PR #83 已部署；本阶段不调用 GitHub，也不修改共享检查器。本地仓库中的旧检查器文件不作为注册工具已部署能力的替代事实源，工具是否可执行以实际 check 回执为准。

## AC-08：删除失败保留旧机会

1. 通过产品新增入口建立 A、B、C，将 B 标为已读；成功删除 A，核对 B/C、统计及 A 撤销入口。
2. snapshot_storage 后开启故障，真实点击删除 B。核对失败提示、B/C 仍在、统计不变、入口仍对应 A；unchanged_storage 确认持久化未变。
3. 同页关闭故障，真实撤销 A；核对 A/B/C 和统计，刷新后再次核对，撤销入口不保留。
4. 再删除 A，重复删除 B 的故障与存储核对；同页关闭故障后真实重试删除 B，入口改为 B。撤销 B 后 A 仍被删除，刷新只保留 B/C。

## AC-09：撤销失败保留恢复机会

1. 成功删除已读 B，核对 A/C 和统计，snapshot_storage 后开启故障。
2. 点击真实撤销 B。核对未恢复提示、A/C 和统计未变、不显示恢复成功、入口仍对应 B；unchanged_storage 确认持久化未变。
3. 同页关闭故障，真实重试撤销 B。核对恢复书名、统计和机会已消耗；刷新后 A/B/C 仍在、总数为三，已读筛选只有 B，无重复恢复或残留撤销入口。
